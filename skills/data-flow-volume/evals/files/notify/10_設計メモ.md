# 通知サービス 設計メモ（架空のテスト用資料）

## 概要

通知サービス（`notify` スキーマ）は、他のサービスから通知の依頼を受け、利用者のスマートフォンアプリへプッシュ通知を送る。
本チームの担当は `notify` スキーマのみ。依頼元のサービスと、スマートフォンアプリは別チームの担当である。

## 処理

1. 依頼元のサービスが通知依頼APIを呼ぶ。依頼1件につき、宛先の利用者は1人。
2. 通知依頼APIが `notify.notification`（通知）に1件登録する。
3. 送信ワーカーが通知サービスの外部（プッシュ配信基盤）へ送り、結果を `notify.delivery_result`（配信結果）に1件登録する。
   失敗したときは最大3回まで再送し、再送のたびに配信結果を1件登録する。
4. 利用者が「201_お知らせ一覧画面」（スマートフォンアプリ）を開くと、自分宛ての通知を新しい順に表示する。1ページ30件。
5. 管理者は「301_配信状況画面」で、配信結果を日ごとに集計して見る。

## テーブル

| テーブル | 主な列 |
| ---- | ---- |
| notify.notification | notification_id, user_id, title VARCHAR(50), body VARCHAR(400), requested_at |
| notify.delivery_result | result_id, notification_id, attempt SMALLINT, result VARCHAR(10), sent_at |
| notify.template_master | template_id, title VARCHAR(50), body VARCHAR(400)（管理者が「302_テンプレート設定画面」で登録。10件程度） |

## 決まっていないこと

- 利用者数と、1人あたりの通知の頻度は、依頼元のサービス側でまだ見積もっていない。
- 通知の保持期間は、要件定義書に記載が無い。

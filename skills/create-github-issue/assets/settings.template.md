# create-github-issue の設定

このファイルは、`create-github-issue` スキルが読む設定である。  
初回に、プロジェクトから読み取った内容と、質問の回答を保存したもので、以後の実行では、質問せずに、これを使う。  
**規約の中身は、書かない。** 規約・手順書の「場所」だけを書く（中身は、実行のたびに、その場所から読む）。  
内容を変えたいときは、「設定を見直したい」と伝えるか、このファイルを直接直す。

## 種別の表

種別は、`.github/ISSUE_TEMPLATE/` のテンプレートから拾う。  
ここには、テンプレートごとの、タイトル接頭辞・ブランチ接頭辞・ブランチを切るかを書く。  
規約にブランチの決まりがあるときは、それを優先して書く。  
表に無い種別は、既定の規則（タイトル接頭辞はテンプレートの title、ブランチ接頭辞は bug・fix・不具合を含めば `fix/`、それ以外は `feature/`、ブランチは切る）で扱う。  

| 種別（テンプレートのファイル名） | タイトル接頭辞 | ブランチ接頭辞 | ブランチを切るか |
|---|---|---|---|
| `<例：bug_report>` | `<例：[bug] >` | `<例：fix/>` | 切る |
| `<例：feature_request>` | `<例：[feature] >` | `<例：feature/>` | 切る |
| `<例：docs_request>` | `<例：[docs] >` | `<例：feature/>` | `<切る／切らない>` |

- ブランチを切らない種別（設計書を別の場所に置くものなど）がなければ、すべて「切る」にする。  

## 起点ブランチの規則

`resolve_base_branch.py` が読む表である。  
値を書かない（または `<` で始まるままにする）項目は、既定で動く。  

| 項目 | 値 |
|---|---|
| 起点ブランチの規則（正規表現） | `^(main\|master\|develop\|development)$` |
| 既定の起点ブランチ | `<例：develop>` |
| リモート名 | `origin` |
| ブランチ名の形式 | `<ブランチ接頭辞>#<番号>-<スラッグ>` |

- 規則に合うブランチが複数あるときは、候補を見せて、ユーザーが選ぶ。  
- 「ブランチ名の形式」は、スクリプトは読まず、SKILL.md の手順4で使う。  

## 読むもの

Issue を作る前に読む場所を書く。  
中身は写さない。  

| 読むもの | 何を取るか |
|---|---|
| 親 Issue（あれば） | 親 Issue の番号、子 Issue の分け方 |
| `AGENTS.md` | Issue・ブランチ・コミットに関する決まり |
| 既存の同種の Issue | 書き方・構成の見本 |
| `<例：docs/ のブランチ・コミット規約>` | `<例：ブランチ名・起点ブランチの規則>` |

# ひな形：Issue 本文

`<…>` を、その Issue の内容に置き換える。  
書き方の決まりは、[作成要領.md](作成要領.md) を参照する。  
「（該当するときだけ）」と付いた行は、当てはまらなければ消す。  

Issue フォームの項目は、`python scripts/get_issue_template_fields.py <種別>` で取る。  
このひな形の見出しのうち、フォームの項目にあたるものは、フォームの `label` に合わせて書き換える。  
フォームに無い節（決定事項・未決事項・作業項目・受け入れ条件）は、手書きの節として、フォームの項目の後ろに置く。  

---

```markdown
### 背景・目的

<なぜ必要か、何をするか>
親 Issue：#<親 Issue の番号>（該当するときだけ）

### 対象

- <対象（機能・画面・ファイル・文書など）>：`<置き場所のパス>`

### 更新・追加内容

<何をどう変えるか、何を足すか>

| <列名> | <列名> |
|---|---|
| <内容> | <内容> |

#### 決定事項

- <決まったこと>（<YYYY-MM-DD> 決定）

#### 未決事項

- <決まっていないこと>

### 作業項目

チェックが付いているものは、終わった作業です（<YYYY-MM-DD>時点）。

**方針の決定・調整**

- [ ] <読むもの>を読み、対象と範囲を確かめる
- [ ] <実装の前に決めること>（該当するときだけ）

**実装・試験**

- [ ] <作業>
- [ ] <テストの作成と実行>

**文書**

- [ ] <文書への反映>

**報告**

- [ ] <担当>に、完了を報告する

### 受け入れ条件

- [ ] <終わったかを確かめられる条件>
- [ ] <終わったかを確かめられる条件>

### 補足・関連

- 親 Issue：#<親 Issue の番号>（該当するときだけ）
- 関連する Issue：#<番号>（該当するときだけ）
- 読んだ資料：`<資料の場所>`
```

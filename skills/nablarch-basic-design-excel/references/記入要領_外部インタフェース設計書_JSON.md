# 記入要領: 外部インタフェース設計書(JSON)

## 資料の目的

1つのJSON電文（APIのリクエストまたはレスポンス）について、フィールド単位の型・桁・必須・ドメインを定義する。
**電文1つにつき1ファイル**作成する（リクエスト用・レスポンス用は別ファイル）。
システム機能設計書(Webサービス)の「2.3.1／2.5.1 項目定義」から参照される、項目定義の一次情報。

## シート『1. 外部インタフェース仕様』

| 位置（行） | 項目名 | 記入内容（Excelのセルコメントより） | 記入例（B10101P_顧客検索応答電文） |
|---|---|---|---|
| 7行目 | 入出力種別／相手先 | 入力/出力、連携相手（未定なら「-」）。相手先は外部機関名称・部署名・システム名など。複数ある場合は複数記述する（例：XX1システム、XX2システム） | - |
| 8行目 | 入出力取引ID/名称／ファイルID・電文ID | 対応する取引ID/取引名（機能名称）、電文ID | `B10101/顧客検索` |
| 9行目 | 目的・概要 | インタフェースの利用目的・概要を記述する | 「他システムに顧客検索の検索結果を返送する。」 |
| 14行目 | 作成条件 | ファイルが作成される条件を記述する。対象データが0件の場合も合わせて作成条件欄に記述する | （通常は取引が正常終了した場合、等） |
| 18行目 | 媒体／データ形式 | **JSON電文では媒体は記載不要**。データ形式は「階層構造(JSON形式)」固定（下記「選択欄」を参照） | データ形式＝階層構造（JSON形式） |
| 21行目 | 授受方式／ﾌｨｰﾙﾄﾞｾﾊﾟﾚｰﾀ | 授受方式は伝送方式または媒体送付方法を自由記述（例：伝送ファイルなら「FTP」「HULFT」）。**フィールドセパレータはJSON電文では記載不要**（選択欄なし） | 授受方式のみ記入 |
| 22行目 | 暗号化／改行コード | 暗号化有無を選択。「有り」の場合は暗号化の詳細（通信暗号化/ファイル暗号化/項目暗号化のいずれか）を記載する。**改行コードはJSON電文では記載不要** | 暗号化＝無し |
| 24行目 | 文字コード／レコード長(ﾊﾞｲﾄ) | 文字コード。**レコード長はJSON電文では記載不要**（固定長ならバイト数、可変長なら最大バイト数） | UTF-8 |
| 25行目 | 処理サイクル | 処理サイクルを選択し、括弧内に詳細を記述する | 随時（詳細：都度） |
| 28行目〜 | 特記事項 | 記載が必要だが特定の項目がない場合に記述する（例：標準値以外の文字設定など）。罫線はE28〜E31の4行分のみ。長文は句点等の意味のまとまりで区切り、`build_external_if_json.py`の電文定義JSONでは`remarks`を配列（1要素=1行）にして渡すと、E28から連番セルへ展開される（4行を超えるとエラーになるため、電文定義側で行数を削る） | なし。 |

### 選択欄（媒体・データ形式・暗号化・改行コード・処理サイクル・入出力種別）

Nablarch公式テンプレートの原本では、これらの項目はExcelのチェックボックス型フォームコントロール（29個）で選択する形式だった。
しかしこの形式は`openpyxl`で読み込んで保存すると跡形もなく消えてしまう（VML／ctrlPropsという、セルの入力規則とは別の仕組みのため、`openpyxl`はもちろん本スキルの`restore_shapes.py`でも復元できない）。
そこで本スキルでは、同じ選択肢を**「□ 選択肢」のセル文字列**に置き換えている。原本のチェックボックスと同様、**選択肢1つにつき1セル**を割り当てており、縦横の配置も原本のレイアウトに合わせてある。

| 項目 | セルと内容 |
|---|---|
| 入出力種別 | `E7`=`□入力` ／ `I7`=`□出力`（横並び） |
| 媒体 | `E18`=`□伝送ファイル` ／ `E19`=`□その他`（縦並び。その他選択時は`G19:P19`の括弧に理由を記入。JSON電文では通常未記入のままでよい） |
| データ形式 | `U18`=`□固定長（ﾌｨｰﾙﾄﾞｾﾊﾟﾚｰﾀなし）` ／ `AB18`=`□固定長（ﾌｨｰﾙﾄﾞｾﾊﾟﾚｰﾀあり）` ／ `U19`=`□可変長（ﾌｨｰﾙﾄﾞｾﾊﾟﾚｰﾀあり）` ／ `AB19`=`□その他`（その他選択時は`AD19:AI19`の括弧に理由を記入） ／ `U20`=`□階層構造（XML形式）` ／ `AB20`=`☑階層構造（JSON形式）`。**JSON電文では`AB20`が既定でチェック済み**。他の電文形式に流用する場合のみ選び直す |
| 暗号化 | `E22`=`□無し` ／ `E23`=`□有り`（縦並び。有り選択時は`G23:P23`に、実施する暗号化の詳細（通信暗号化/ファイル暗号化/項目暗号化のいずれか）を記入） |
| 改行コード | `U22`=`□CR` ／ `Y22`=`□LF` ／ `AD22`=`□CR+LF`（横並び） ／ `U23`=`□無し` ／ `Y23`=`□その他`（その他選択時は`AA23:AI23`の括弧に理由を記入）。JSON電文では通常未記入のままでよい |
| 処理サイクル | `E25`=`□日次`（詳細欄`G25:Q25`） ／ `R25`=`□週次`（詳細欄`T25:AD25`） ／ `E26`=`□月次`（詳細欄`G26:Q26`） ／ `R26`=`□年次`（詳細欄`T26:AD26`） ／ `E27`=`□随時`（詳細欄`G27:Q27`） ／ `R27`=`□その他`（詳細欄`T27:AI27`）。選んだ選択肢の詳細欄に、どのタイミングで実行するか（例：毎週月曜10:00）を記入する |

選択したら該当する`□`を`☑`に書き換える（未選択の`□`は消さずにそのまま残す）。

**フィールドセパレータ（Q21の右側）には選択欄が無い**。この項目はJSON電文の設計書では対象外として扱われており（元のテンプレートでも取り消し線が引かれている）、チェックボックス自体が存在しない。何も記入せず空欄のままにする。

## ⚠️グレーアウトされたセルは記入しない

このテンプレートは、**記入不要の欄をグレーで塗って**いる。白いセルだけが記入対象である。
グレーのセルに書くと、様式の意図に反するうえレビューで戻る。

`apply_mapping.py` は塗りを見ないため、書けてしまう。記入前に必ず対象セルの塗りを確認すること。

## シート『2. レコード構成』

**記入するのは、ルートレコードのレコード名1行だけである。**

- No.2以降の行（A10〜）はグレーアウトされている。複数行は書かない。
- レコード名（B列）以外の列（ﾚｺｰﾄﾞﾀｲﾌﾟ名・識別方法・長さ・繰り返し回数・繰り返し単位・ソートKEY）もグレーアウトされている。書かない。
- 子レコード（ネストしたオブジェクト・配列）は、この一覧ではなく**レコード構成イメージ**と『【レコード名】』シートのブロックで表す。

Nablarch標準サンプル（`外部インタフェース設計書(JSON)_サンプル.xlsx`）も、3レコードある電文で
レコード構成には「振込依頼」1行しか書いていない。

### レコード構成イメージ（A19の下）

レコード**同士**の入れ子関係を示す欄。項目は書かない（項目一覧の繰り返しになるため）。
階層が無い電文（レコード1件）では書くことが無いので**省略する**。

セル内で改行しても表示されないため、**1行につき1セル**へ書く。
階層は列をずらして表す（親をA列、子をB列）。

```
A20: 評価依頼
B21: └ 回答明細（answers：繰り返し）
```

## シート『【レコード名】』の構造（3ブロック×7行）


電文内に複数のレコード（ネストしたオブジェクトや配列）がある場合、その一覧を定義する（見出しは7〜8行目）。
**JSONの場合はレコード名を1件のみ記述する**（Excelセルコメント B8より。ネストが無いシンプルなJSON電文であれば、このシートには行が1行しか無くてよい）。

| 項目名 | 記入内容 |
|---|---|
| No. | 通し番号 |
| レコード名 | 例：「顧客」「顧客一覧」 |
| ﾚｺｰﾄﾞﾀｲﾌﾟ名 | 単一レコードか繰り返し（配列）かの種別名 |
| 識別方法 | 配列の要素を識別するキー等 |
| 長さ(Byte) | 固定長ファイルの場合のみ使用（JSON電文では通常「-」） |
| 繰り返し回数 | 配列の場合の上限件数など |
| 繰り返し単位 | 繰り返しの単位（件、行 等） |
| ソートKEY項目名／昇順・降順 | 配列をソートして返す場合のキー項目と順序 |

このシートは**3つのブロック**に分かれており、1ブロックが1レコードに対応する。
**電文1つにつきシート1枚**であり、レコードごとにシートを分けるのではない。

| ブロック | レコード名 | レコードID | データ行 | 行数 |
|---|---|---|---|---|
| 1 | 7行目 | 8行目 | 10〜16行目 | 7 |
| 2 | 18行目 | 19行目 | 20〜26行目 | 7 |
| 3 | 28行目 | 29行目 | 30〜36行目 | 7 |
| — | データ構成サンプル／データ構成イメージの見出し | 39行目 | 40行目以降 | — |

見出し（No./項目名/…）はブロック1にしかない。ブロック2・3はレコードIDの次の行からデータが始まる。

- **1ブロックは7行しかない。** 項目数がこれを超える場合は行を挿入して広げる（後述）。
- レコードが4件以上ある場合だけ、シートを複製する。
- 使わないブロックは、値・罫線・塗りを消して空白にする。

### 項目数が7件を超える場合

`extend_table_rows.py` は**使えない**。同スクリプトは行を挿入せず最終行の書式を下へ複製するだけなので、
下にあるブロック2・3の領域を上書きし、既存の結合セルと衝突して失敗する。

`insert_rows.py` を使う。行を挿入し、挿入位置より下の結合セル・行高・入力規則を同じだけずらす。

### データ構成サンプル／データ構成イメージ

見出しは39行目の左右に分かれている。粒度が違う。

| 欄 | 場所 | 内容 |
|---|---|---|
| データ構成サンプル | A39の下（左側） | **実データの例**。値入りのJSON。必ず記入する |
| データ構成イメージ | Y39の下（右側） | 項目レベルまで含めた構造の見取り図。項目一覧と重複するため、通常は記入しない |

サンプルもセル内改行では表示されないため、**1行につき1セル**へ書く。
値は `"..."` のような伏せ字ではなく、実際にありえる値を入れる。

## シート『【レコード名】』（1電文1シート。シート名は`3.1.振込依頼`のようにリネーム）

I5:AL8には、このシートを複製して使う際の注意事項（「フォーマット定義ファイル自動生成ツール」を使う場合に削除してはいけない列の一覧等）がセル文字列として記載されている（`duplicate_sheet.py`でシートを複製した場合、図形は複製先に引き継がれないが、このセル文字列は自動的に複製される）。**このセルの文言は削除しないこと。**

このシートは「2. レコード構成」シートに定義したレコード種類ごとに1シート作成する。**JSONの場合はレコードが1種類なので通常1シートのみでよい**（Excelセルコメント A5より）。

見出し（9行目）：`No. / 項目名 / 項目ID / ドメイン名 / 必須 / データ型 / 桁数 / 多重度 / ﾃﾞﾌｫﾙﾄ値 / ﾌｫｰﾏｯﾄ仕様 / 備考`

| 位置 | 項目名 | 記入内容（Excelのセルコメントより） | 記入例 |
|---|---|---|---|
| 上部（7〜8行目） | レコード名／レコードID | このシートが対応するレコード名とJSON上のキー名 | 顧客／`[client]` |
| 明細行 | No. | 通し番号 | 1, 2, 3 |
| 明細行 | 項目名 | 論理名（日本語） | 顧客ID、顧客名、業種コード |
| 明細行 | 項目ID | インタフェース項目を識別するためのID。**数値のみは不可**。レコード種類ごとに一意になるIDをつける | `clientId`, `clientName` |
| 明細行 | ドメイン名 | 項目のバリデーション仕様をドメイン定義と紐付けるための名称。**ドメイン定義の「ドメイン名(論理)」と一致させること** | 顧客ID、顧客名 |
| 明細行 | 必須 | 入力インタフェースの場合は必須項目であれば「○」。出力インタフェースの場合は必ず値をセットする項目であれば「○」 | ○ |
| 明細行 | データ型 | **プルダウンから選択**（下記の表を参照。自由記述不可） | 半角数字、全角 |
| 明細行 | 桁数 | ドメイン定義書と矛盾しないように記述する。ドメイン名に対して冗長だが、「フォーマット定義ファイル自動生成ツール」使用時は必須列（使用しない場合は列を削除してもよい） | 10, 128 |
| 明細行 | 多重度 | 項目の多重度。数値、または`最小数..最大数`（上限なしの場合は`*`） | `1`, `0..15`, `1..*` |
| 明細行 | ﾃﾞﾌｫﾙﾄ値 | 値が設定されなかった場合のデフォルト値・固定値があれば記入。文字列項目は`"1"`のようにダブルクォートで括り、数値項目は括らない（例：`9999`） | `"1"` |
| 明細行 | ﾌｫｰﾏｯﾄ仕様 | フォーマット編集が必要な場合に記入。入力IFは受け取り可能なフォーマット、出力IFはどのようなフォーマットに編集するかを記述 | （該当する場合のみ） |
| 明細行 | 備考 | ドメイン定義書と矛盾しないように記述する。ドメイン名に対して冗長なので列を削除してもよい | - |
| 下部「データ構成サンプル」 | 実際のJSON例 | データ構造が複雑な場合、視覚的に理解しやすくする目的で記載する（**必須ではない**） | `{"client": {"clientId": "0000000001", ...}}` |

### データ型のプルダウン選択肢（自由記述不可・この16種類から選ぶ）

半角英字／半角数字／半角カナ／半角英数字／半角英数字記号／半角／全角ひらがな／全角カタカナ／全角／全角(外字含む)／全半角／全半角(外字含む)／符号無数値／符号付数値／オブジェクト／真偽値

## 記入時のポイント

- 「項目ID」はプログラム側のフィールド名と完全一致させる（実装時にそのまま使われる）。
- 「ドメイン名」は必ずドメイン定義書に存在する名称を使う。存在しない場合は先にドメイン定義書へ追加する。
- 「データ型」は必ず上記16選択肢から選ぶ。リストにない表現（例：「半角数字10桁」のように桁数を混ぜて書く等）は誤り。桁数は別列の「桁数」に分離して書く。
- ネスト構造（配列の中の配列等）がある場合、親レコードの項目に子レコード名を記載し、子レコードは別シートとして分ける（テンプレートの『【レコード名】』シートを複製）。

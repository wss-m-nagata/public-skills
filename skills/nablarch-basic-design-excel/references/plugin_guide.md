# Claude for Microsoft 365（Claude in Excel）利用ガイド

## Must4とは

このプロジェクトの基本設計書一式（Nablarch開発標準の`030_アプリ設計`配下、9カテゴリ）のうち、
バックエンド（画面を持たないAPI/バッチ系システム）の基本設計として**最低限必須**と判断した4カテゴリ・8テンプレートを指す。

1. システム機能一覧
2. システム機能設計書（Webサービス／バッチ）
3. 外部インタフェース一覧／外部インタフェース設計書(JSON)／WebサービスAPI一覧
4. テーブル一覧／テーブル定義書

ドメイン定義書・コード設計書・メッセージ設計書・採番一覧・ネット/ジョブフロー設計・単体テスト仕様書は、今回は対象外（必要になった時点で追加検討する）。

## このフォルダの目的

このフォルダは、Claude for Microsoft 365で上記Must4を作成する際に、参照させるための一式です。
スクリプトを実行できないClaude for Microsoft 365向けに、
「編集対象そのもの」「内容の記入例」「どこに何を書くか」「構造の保護ポイント」の4点を明文化しています。

## ⚠️着手前に必ず確認：データ型の不整合

テーブル定義書テンプレートの「データ型」プルダウンは既定でOracle型名一覧になっているが、
本プロジェクトの実行環境はPostgreSQLである。
詳細と対応方針は `記入要領_テーブル定義書.md` の冒頭を参照し、**テーブル定義書に着手する前に**対応方針を確定させること。

## ⚠️着手前に必ず確認：PJ名/システム名/サブシステム名は変更履歴シートにのみ入力

8テンプレートすべてで、`表紙`と`変更履歴`を除く全シートのPJ名/システム名/サブシステム名欄（E1〜E3）は、
`変更履歴`シートの値を参照する**数式**になっている。
他のシートへ直接入力すると数式が壊れる。
詳細は`記入要領_共通シート.md`を参照。

## ローカル実行スクリプトとの役割分担

このフォルダ（`references/`）はClaude for Microsoft 365向けの**参照資料**。
実際にExcelへ値を書き込む処理は `../scripts/`（`apply_mapping.py` / `verify_layout.py`等）で行う。
ローカルスクリプト側では、数式セルへの誤書き込みやテンプレートの罫線範囲外への書き込みを自動的にブロックする安全装置を備えている。詳細はスキル本体（`SKILL.md`）を参照。

## ⚠️着手前に必ず確認：記入可能行数を超える場合はClaude for Microsoft 365だけで完結させない

下記の依頼文は「新しい行や列の追加・削除は行わないでください」と明記している。
Claude for Microsoft 365には`extend_table_rows.py`・`insert_rows.py`に相当する安全な行追加手段が無く、
罫線・結合セル・入力規則を壊さずに行を増やせないため、この制約は外さない。

そのため、依頼する**前に**確定済み内容の件数と、対象シートの記入可能行数（`構造メモ_*.md`の「使用範囲の目安」「罫線が設定されているセル」を参照。外部インタフェース設計書(JSON)は「読み取りにくい点の補足」の3ブロック構成も参照）を突き合わせ、収まるかを確認する。

- **収まる場合**：そのまま依頼してよい。
- **収まらない場合**：Claude for Microsoft 365だけでは安全に完了できない。ローカル実行環境（`scripts/extend_table_rows.py`または`scripts/insert_rows.py`）で先に行を拡張してから、その拡張済みファイルをClaude for Microsoft 365へ渡して値の入力のみを依頼する。
- **ローカル実行環境も無い場合**：行数を仮の範囲に収めたり、複数シートに分割したりして依頼を進めてはいけない。作業を中止し、ユーザーに「テンプレートの記入可能行数（n行）を要求件数（m件）が超えており、ローカル実行環境での事前の行拡張が必要」と報告する。

## フォルダの中身

| ファイル | 役割 |
|---|---|
| `記入要領_共通シート.md` | 表紙・変更履歴・目次の記入方法（全テンプレート共通） |
| `記入要領_*.md`（8ファイル） | 各テンプレートの「どこに」「何を」「どう書くか」の説明。項目の意味・記入例・他資料との対応関係をまとめたもの |
| `構造メモ_*.md`（8ファイル） | 各テンプレートの結合セル・背景色・フォント色・行列サイズ・罫線・入力規則（プルダウン）を機械抽出したもの。編集時に壊してはいけない箇所の一覧 |
| `extract_structure.py` | 構造メモを生成したスクリプト。テンプレートに変更が入った場合は再実行して更新する |

`記入要領_*.md` と `構造メモ_*.md` はファイル名の末尾（テンプレート名部分）で対応しています。
例：`記入要領_テーブル定義書.md` ⇔ `構造メモ_テーブル定義書.md`。
`記入要領_共通シート.md` に対応する構造メモは無い（表紙・変更履歴・目次は全テンプレートで共通のため、各`構造メモ_*.md`内にそれぞれ含まれている）。

対応する「編集対象の空テンプレート」と「記入サンプル」は `../assets/templates/` にあります。

| カテゴリ | 空テンプレート（`assets/templates/フォーマット/`） | 記入サンプル（`assets/templates/サンプル/`） |
|---|---|---|
| ①機能一覧 | `システム機能一覧_(サブシステムID)_(サブシステム名).xlsx` | `システム機能一覧_サンプル.xlsx` |
| ②機能設計書(Webサービス) | `システム機能設計書(Webサービス)_(取引ID)_(取引名).xlsx` | `システム機能設計書(Webサービス)_サンプル.xlsx` |
| ②機能設計書(バッチ) | `システム機能設計書(バッチ)_(取引ID)_(取引名).xlsx` | `システム機能設計書(バッチ)_サンプル.xlsx` |
| ③外部インタフェース一覧 | `外部インタフェース一覧_(サブシステムID)_(サブシステム名).xlsx` | `外部インタフェース一覧_サンプル.xlsx` |
| ③外部インタフェース設計書(JSON) | `外部インタフェース設計書_(電文ID)_(電文名)_(JSON).xlsx` | `外部インタフェース設計書(JSON)_サンプル.xlsx` |
| ③WebサービスAPI一覧 | `WebサービスAPI一覧_(サブシステムID)_(サブシステム名).xlsx` | `WebサービスAPI一覧_サンプル.xlsx` |
| ④テーブル一覧 | `テーブル一覧.xlsx` | `テーブル一覧_サンプル.xlsx` |
| ④テーブル定義書 | `テーブル定義書_(サブシステムID)_(サブシステム名).xlsx` | `テーブル定義書_サンプル.xlsx` |

さらに、このサンプルプロジェクト自体の実例（B1顧客管理システム）を `../assets/templates/B1実例/` に用意しています。
Nablarch標準サンプルより実業務に近いイメージが欲しい場合はこちらも参照してください。

## Claude for Microsoft 365での依頼の仕方（テンプレート文）

各設計書に着手する際、以下を**すべて**Claude in Excelに読み込ませた上で依頼してください。

1. 編集対象の空テンプレート（該当ファイルを開いた状態、またはアップロード）
2. 対応する記入サンプル（Nablarch標準サンプル、必要なら実例も）
3. `記入要領_共通シート.md`（表紙・変更履歴・目次の記入方法。初回のみでよい）
4. 対応する `記入要領_*.md`（どこに何を書くかの説明）
5. 対応する `構造メモ_*.md`（壊してはいけない構造・入力規則の一覧）
6. 確定済みの記載内容（調査・整理資料から確定した項目）

その上で、次のような指示文を添えることを推奨します。

> 添付の空テンプレートに、以下の内容を入力してください。
> 記入例（サンプル）と同じ書き方・粒度に合わせてください。
> 構造メモに記載された結合セル・背景色・フォント色・行列サイズ・罫線は一切変更しないでください。
> 新しい行や列の追加・削除は行わないでください。
> 既存のセルの書式（色・罫線）はそのまま残し、値のみを入力してください。
> セルに既に数式が入っている場合は上書きしないでください（PJ名・システム名・サブシステム名は「変更履歴」シートにのみ入力し、他のシートには入力しないでください）。
> 「入力規則（プルダウン等）」に記載された列には、構造メモに列挙された選択肢以外の値を入力しないでください。
> 判断に迷う項目があれば、値を仮置きせずに質問してください。
>
> 入力内容：
> （ここに確定済み内容を貼り付け）

## 反映後の確認ポイント

Claude in Excelは変更差分をハイライト表示し、承認前に確認できます。
承認前に、必ず以下を目視確認してください。

- 行が増減していないか
- 背景色・罫線が消えていないか、意図せず広がっていないか
- 結合セルが解除・変更されていないか（特に `構造メモ` に記載の範囲）
- プルダウン列に、構造メモに列挙されていない値が入っていないか
- 数式が入っているセル（テーブル定義書の型/桁チェック等）を誤って値で上書きしていないか

## この構造メモの限界（自動抽出できていない・不完全な情報）

`extract_structure.py` は結合セル・背景色・フォント色・行列サイズ・罫線・入力規則（プルダウン）・条件付き書式の有無・シート保護の有無を抽出しますが、以下は抽出できていません。
最終確認は目視で行ってください。

- セルの表示形式（日付・数値のフォーマット）
- 条件付き書式の**具体的なルール内容**（設定の有無のみ検出。ルールの詳細は未抽出）
- 画像・図形オブジェクト・**チェックボックス等のフォームコントロール**（下記「フォームコントロールの注意」を参照）
- 入力可能セルの制限範囲の詳細（シート保護は有無のみ検出）

## フォームコントロールの注意（重要）

外部インタフェース設計書(JSON)の**空テンプレート**（`assets/templates/フォーマット/`配下）は、原本にあったチェックボックス形式のフォームコントロールを、**「□ 選択肢」のセル文字列**（該当するものを`☑`に書き換える形式）に置き換え済み。セルに直接文字を打つのではなく、選択肢の中から該当するものの`□`を`☑`に書き換える。詳細（対象セル・選択肢）は`記入要領_外部インタフェース設計書_JSON.md`の「選択欄」を参照。

一方、`assets/templates/サンプル/`・`B1実例/`配下のファイルは人が手作業で作成したものであり、原本どおり実際のチェックボックス形式のフォームコントロールを保持している（`ctrlProps`として検出できる）。これらは記入内容の参考として読むだけにとどめ、編集対象にはしない。

他の7テンプレートにも図形・描画オブジェクト（`drawing.xml`／`vmlDrawing`）が含まれているが、こちらは表紙の機密区分表示やセルコメント（入力ヒント）であり、チェックボックス（`ctrlProps`）ではない。

## 記入要領そのものの限界

各`記入要領_*.md`は、公式テンプレートの列を機械的に全列ダンプした上でセルコメント（入力ヒント）も確認して作成しているが、結合セルの正確な入力可能範囲まで全パターンを網羅しているわけではない。実際に記入する際、想定と異なる挙動（結合範囲のズレ等）に気づいたら、その場で構造メモを見直すこと。

テーブル定義書の「INDEX」列（1〜7の番号列）の記載ルール（種別：`U`ユニーク／`R`逆キー／`B`ビットマップ／`C`クラスター、組み合わせ可。各項目行には付与順と昇順(`A`)/降順(`D`)を記述）は`記入要領_テーブル定義書.md`を参照。RDBMSにより存在しない種別があるため、PostgreSQL採用時にどの種別が使えるかは別途確認が必要。

## テンプレートを更新した場合

Nablarch標準側でテンプレートが更新された場合は、以下を再実行してメモを更新してください。

```bash
python ../scripts/extract_structure.py "<対象xlsxパス>" "構造メモ_<名称>.md"
```

（このコマンドは`references/`ディレクトリ内で実行する想定。スキルのルートディレクトリから実行する場合は`scripts/extract_structure.py`と`references/構造メモ_<名称>.md`のように読み替える）

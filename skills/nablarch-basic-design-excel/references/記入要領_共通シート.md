# 記入要領: 共通シート（表紙・変更履歴・目次）

## 対象

Must4の8テンプレートすべてに共通して存在する3シート。
各設計書の「記入要領_*.md」には記載していないため、必ずこちらも合わせて参照すること。

## ⚠️最重要：PJ名/システム名/サブシステム名は「変更履歴」シートにのみ入力する

**8テンプレート共通の仕組み**：各シート1〜3行目のPJ名・システム名・サブシステム名の値欄（E1・E2・E3）は、`表紙`と`変更履歴`を除く全シート（`目次`、および本体シート）で

```
=IF(INDIRECT("変更履歴!E1")<>"",INDIRECT("変更履歴!E1"),"")
```

という**数式**になっており、`変更履歴`シートのE1/E2/E3を参照して自動表示している。

- 値を入力してよいのは**`変更履歴`シートのE1（PJ名）・E2（システム名）・E3（サブシステム名）のみ**。
- 他のシートのE1〜E3に直接文字を入力すると、**この数式を上書きして壊してしまう**。
- ローカルスクリプト（`apply_mapping.py`）は数式セルへの書き込みを既定でブロックする安全装置を持つが、Claude for Microsoft 365で手作業に近い形で編集する場合は、この仕組みを事前に伝えておくこと。

## シート『表紙』（セルベースのレイアウト）

`assets/templates/フォーマット/`配下のテンプレートでは、表紙のプロジェクト名・成果物名・サブシステム名等はセルベースのレイアウトになっている（全8テンプレート共通）。

| セル | 内容 | フォント | 記入例 |
|---|---|---|---|
| J12 | プレースホルダー。**静的テキスト**、手動で置き換える | 18pt太字・中央揃え | `[プロジェクト名]` → `サンプルプロジェクト` |
| J14 | 成果物名（例：「テーブル定義書」）。**テンプレート固有の固定値、変更しない** | 18pt太字・中央揃え | （編集不要） |
| J16 | プレースホルダー。**静的テキスト**、手動で置き換える | 18pt太字・中央揃え | `[サブシステム名]` → `顧客管理システム` |
| J19 | 版数。**静的テキスト** | 14pt・中央揃え | 「第1.0版」 |
| I21（結合セルI21:K21） | **数式**。`変更履歴`シートの変更日列の最大値＝最終更新日を自動表示。**直接編集しない** | 14pt・中央揃え | （自動計算） |
| J23 | **数式**。`変更履歴!E1`（PJ名）を自動表示。**直接編集しない** | 9pt | （自動計算） |
| J25 | **数式**。`変更履歴!E3`（サブシステム名）を自動表示。**直接編集しない** | 9pt | （自動計算） |
| J28 | プレースホルダー（会社名）。**静的テキスト**、手動で置き換える | 13pt・中央揃え | `[会社名]` → 実際の会社名 |
| J30 | プレースホルダー（部門名）。**静的テキスト**、手動で置き換える | 13pt・中央揃え | `[部門名]` → 実際の部門名 |

- D11:P17に罫線の枠(box)があり、J12/J14/J16(プロジェクト名・成果物名・サブシステム名の3行)を囲んでいる。この枠と行の高さ(12/14/16行目=21.0、19行目=17.25、21行目=18.0、28〜30行目=18.75)は崩さないこと。
- J12・J16の`[ ]`プレースホルダーは、角括弧ごと実際の値に置き換える（角括弧を残さない）。J28・J30の会社名・部門名も同様。
- J19（版数）は「変更履歴」シートの最新行の版数と**手動で**一致させる（数式ではなく静的テキストなので、変更履歴を更新したら表紙側も忘れずに書き換える）。
- J23・J25は**数式なので直接編集しない**。値は`変更履歴!E1`・`変更履歴!E3`から自動的に反映される。J12・J16（プレースホルダー）とJ23・J25（数式）で、プロジェクト名・サブシステム名が二重に（大きな見出しと小さな注記として）表示される構成になっている。

### 図形（テキストボックス）について

Nablarch標準の原本テンプレートにあった「関係者外秘」「関係者限り」等の機密区分表示の図形は、**このスキルのテンプレートにもそのまま残っている**（ユーザーの判断で削除せず保持する方針）。
表紙のプロジェクト名・成果物名・サブシステム名等の主要情報はセルベースのレイアウトに再設計済みだが、機密区分の図形自体は別物として維持している。

- この図形は`openpyxl`で保存すると消えるため（後述）、`apply_mapping.py`・`duplicate_sheet.py`・`extend_table_rows.py`はいずれも保存の最終段階で`scripts/restore_shapes.py`（`xlsx_common.save_with_shapes()`経由）を通し、`表紙`シートの図形を毎回復元している。**このスキルのテンプレートに対しても実際に機能する、常時必要な処理**であり、原本テンプレート専用の備えではない。
- `verify_layout.py`の図形消失チェックは、この復元が正しく行われたかを確認する目的で毎回意味を持つ。図形が消えたと報告された場合は、`restore_shapes.py`の復元に失敗している可能性が高いので原因を調査すること。
- シートを複製した場合（`duplicate_sheet.py`）、新規シートには元の同名シートの図形しか復元されない仕組みのため、複製元シートに図形がある場合（例：外部インタフェース設計書(JSON)の「【レコード名】」シート）は、複製後のシートに図形が引き継がれない。この点は個別テンプレートの記入要領・構造メモ側で補足する。

### ⚠️重要：作成・更新の元ファイルには必ず`assets/templates/フォーマット/`配下のテンプレートを使う

**`assets/templates/フォーマット/`配下のテンプレートは、生成AI（本スキルのスクリプト）が扱いやすいように、フォームコントロールや図形オブジェクトを意図的に極力減らして作られている。**
一方、`サンプル/`・`B1実例/`・`A1実例/`配下のファイルは**人が手作業で編集して作成したもの**であり、原本のNablarch標準どおり表紙のプロジェクト名・成果物名・サブシステム名が今も図形（テキストボックス）のまま含まれているなど、図形・オブジェクトを保持している。

`apply_mapping.py`・`duplicate_sheet.py`・`extend_table_rows.py`・`restore_shapes.py`はいずれも「元ファイル」に指定されたファイルの図形をそのまま複製後ファイルへコピーする。
**もし作成・更新の元ファイルとして`フォーマット/`配下のテンプレートではなく`サンプル/`・`B1実例/`・`A1実例/`配下のファイルを誤って指定すると、これらが保持する図形（人手による編集の産物）がそのままコピーされ、既に反映されているセルベースの表紙（J12/J14/J16等）に、古い図形ベースの表紙が重なって表示される二重表示の事故が起きる**。

- これらの実例・サンプルファイルは、**記入内容の書き方を参考にする（開いて読む）ためだけ**に使う。作成・更新対象のファイルそのものとしては使わない。
- 一連の処理（シート複製→行拡張→値反映→検証）の「元xlsxパス」は、**必ず`フォーマット/`配下のテンプレートから始まる、直前のステップで自分が出力したファイル**（最初のステップであれば`フォーマット/`配下の空テンプレートのコピー、または既存の`設計書/`配下のファイル）を指定する。サンプル・実例ファイルを一連の処理の入力に混ぜない。

## シート『変更履歴』

まずこのシートのE1・E2・E3にPJ名・システム名・サブシステム名を入力する（上記の通り、これが全シート共通の唯一の入力元）。

| 列 | 内容 | 記入例 |
|---|---|---|
| No. | 通し番号 | 1 |
| 版数 | 表紙（J19）の版数と一致させる | 第1.0版 |
| 変更日 | 変更を行った日付 | 2026-08-20 |
| 区分 | 「新規」または「変更」 | 新規 |
| 変更箇所（項番等） | 変更した章番号（新規作成時は「-」） | - |
| 変更内容 | 変更の概要（新規作成時は「新規作成」） | 新規作成 |
| 担当者（AF列） | 変更を行った担当者名 | 山田太郎 |

- 初版作成時は1行のみ（No.1、区分=新規、変更箇所=`-`）を記入する。
- 以降、内容を変更するたびに行を追加し、版数を上げる。既存行は変更しない（履歴として残すため）。
- 表紙のI21セル（最終更新日）はこの変更日列から自動計算されるため、変更日さえ正しく入力すれば表紙側は自動的に最新化される。

### ⚠️「担当者」列（AF列）を埋めないと、全シートの「作成」「変更」欄が空欄のままになる

各シートの1〜2行目には、PJ名等とは別に「作成」「変更」という欄（ラベルはAA1/AA2、値はAC1/AG1、AC2/AG2）があり、**これも変更履歴シートを参照する数式**になっている。ただし参照元はE列ではなく、この担当者列（AF列）と変更日列（D列）。

- `変更履歴!AC1` = `=IF(AF8="","",AF8)` → 初版（8行目）の担当者名を「作成」欄に表示
- `変更履歴!AG1` = `=IF(D8="","",D8)` → 初版（8行目）の変更日を「作成」欄の日付に表示
- `変更履歴!AC2` = 最新行（9行目以降で入力済みの最後の行）の担当者名を「変更」欄に表示
- `変更履歴!AG2` = 変更日列の最大値（＝最新の変更日）を「変更」欄の日付に表示

つまり、**変更履歴シートの各行にAF列（担当者）を入力しないと、全シート共通の「作成」「変更」欄がいつまでも空欄のまま**になる。No./版数/変更日/区分/変更箇所/変更内容の6列だけ埋めても不十分なので注意すること。

## シート『目次』

- 各設計書の主要な章・シートの見出しが**静的なテキスト**として書かれている。
- **ハイパーリンクではない**（クリックしてジャンプする機能は無い）。そのため、シートを追加・削除・リネームしても自動更新されない。

テンプレートの種類によって、目次の状態と対応が異なる。**この区別を誤ると、不要な編集をしてレイアウトを崩す原因になる。**

### 一覧系テンプレート（システム機能一覧・外部インタフェース一覧・WebサービスAPI一覧・テーブル一覧）

目次には最初から`1. 外部インタフェース一覧`のような**確定済みの文言**が入っている（プレースホルダーではない）。
シートも常に「1」という固定名のまま。
**目次の追記・修正、シート名のリネームのどちらも不要。**

### 「1インスタンス＝1シート」型テンプレート（テーブル定義書・外部インタフェース設計書(JSON)・システム機能設計書）

目次には`1. [論理テーブル名]`のように**角括弧のプレースホルダー**が入っている。
`duplicate_sheet.py`でシートを複製・リネームした場合（例：「顧客」テーブルを追加した場合）は、目次側のプレースホルダーも実際の名称に**手動で追記・修正**する必要がある。
記入の順序としては、本体のシート構成が固まった後の最後に目次を更新するのが効率的。

⚠️**目次の角括弧表記と、実際のシート名の表記は一致しない**（実機で確認済み）。目次の角括弧`[ ]`は「ここを埋める」ことを示す目次側だけの記法であり、実際のシート名自体には角括弧は付かない。例えば外部インタフェース設計書(JSON)の【レコード名】シートは、シート名自体が`【レコード名】`という全角の隅付き括弧（角括弧ではない）で、`duplicate_sheet.py`で複製後は`3.1.顧客一覧`のように隅付き括弧ごと置き換えてリネームする。システム機能設計書の「2.」シートは、シート名自体には角括弧も隅付き括弧も付かず、`2. 取引ID（取引名）`（Webサービス版、括弧は全角）／`2. バッチ処理ID(バッチ処理名)`（バッチ版、括弧は半角）という文字列そのものがプレースホルダーになっている。**シート名を実際の値にリネームする際は、必ず対象の記入要領に書かれた正確な文字列（角括弧の有無・括弧の全角半角）を確認し、`scripts/rename_sheet.py`でリネームする。**

なお、システム機能設計書の目次には「1.1. Webサービス取引概要」「1.1. バッチ取引概要」のような**角括弧の付いていない固定の文言**も並んでいる。これらは「2.」シートと違って**リネーム対象ではない**（シート名は固定のまま）。目次を見て角括弧の有無を確認すれば、リネームすべきシートかどうかを判断できる。

### 迷ったときの見分け方

対象テンプレートの目次シートを開き、角括弧`[ ]`で囲まれたプレースホルダーがあるかどうかを見ればよい。無ければ一覧系（触らない）、あれば1インスタンス1シート型（実際の名称に置き換える）。ただし置き換える際は、目次の角括弧表記をそのまま使うのではなく、実際のシート名の表記（記入要領に記載）を確認すること。

## 記入時の共通ルール

- PJ名／システム名／サブシステム名（各シート1〜3行目）は、Must4の全ファイルで**表記を完全に一致**させる。
- 成果物名（各シート右上、例：「テーブル定義書」）は変更しない（テンプレート固有の固定値）。

## ⚠️各記入要領に書かれた「セル座標」「行番号」は、未編集の元テンプレートでの例に過ぎない

各記入要領（`記入要領_システム機能設計書_Webサービス.md`等）には、説明のためにセル座標（例：`H56`）を記載している箇所があるが、**これは`assets/templates/フォーマット/`配下の未編集テンプレートでの座標であり、対象ファイルにそのまま当てはまるとは限らない**。

`insert_row_block.py`（ブロック複製）・`extend_table_rows.py`（行拡張）を、その行より**前**にあるセクションに対して使うと、それ以降の内容は自動的に下にシフトする（意図した正しい動作）。そのため、同じ「ファイルID」「取引概要」等のラベルでも、対象ファイルの編集履歴によって実際の行番号は記入要領の記載と異なる。**行数が少ないテンプレートはほぼ確実に`extend_table_rows.py`・`insert_row_block.py`で拡張することになるため、行がずれるのは例外ではなくむしろ通常のケースと考えること。**

このズレに気づかず、記入要領に書かれた行番号をそのまま`apply_mapping.py`のマッピングJSONに使うと、意図したセルとは無関係な（多くの場合空の）セルに書き込んでしまう。**値を書き込む前に、必ず対象ファイルの実際のセルでラベル文字列の位置を確認すること。** 確認方法：

- `python scripts/extract_structure.py <対象xlsxパス> <出力md>`を対象ファイル（元テンプレートではなく、ここまでの処理を反映した直前の出力ファイル）に対して実行し、「ラベル→値入力セルの候補」を確認する。
- または、対象シートを開いて該当ラベルの文字列を直接検索する。

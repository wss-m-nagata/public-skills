# 記入要領: テーブル定義書

## ⚠️最優先で確認すべき不整合（必ず着手前に解消すること）

このテンプレートの「データ型」プルダウンは、**既定でOracle用の型名一覧**になっている（`BFILE, BINARY_DOUBLE, ..., VARCHAR2` 等21種類、`データ`シートのA2:A22で定義）。
一方、本サンプルプロジェクトの実行環境は **PostgreSQL 14.2**（根拠は`references/前提条件.md`を参照）であり、実際のテーブル定義書の記入例（B1顧客管理システム）では `SERIAL`, `VARCHAR`, `BIGINT` のようなPostgreSQL系の型名が使われている。
**これらはOracle型のプルダウンリストには存在しない値**であり、そのまま入力するとプルダウンの選択肢と矛盾する。

対応が必要。着手前に以下のどちらにするかを確認すること。

1. テンプレートの`データ`シート（A列）をPostgreSQL用の型名一覧に書き換えてから使う（テンプレート自体の改変になるため、事前に承認を得ること）
2. Oracle型のまま使い、後工程でPostgreSQL用に読み替える前提で運用する（型の対応表を別途用意する必要がある）

## 資料の目的

テーブル一覧に載っている各テーブルについて、カラム単位の論理名・物理名・ドメイン・型・桁・制約を定義する。
**テーブル1つにつき1シート**作成する（テンプレートの『論理テーブル名』シートを、テーブルの数だけ複製してシート名を実際の名称に変える）。

## どこに何を書くか（各テーブルのシート、見出しは8〜10行目）

以下は、Nablarch開発標準の公式ドキュメント（`Nablarch開発標準設計書一覧`の記入要領・テーブル定義書サンプルPDFに記載された凡例）に基づく、**公式な項目定義**。

| 位置 | 項目名 | 公式の定義（原文ママ） | 記入例（企業テーブルのサンプルより） |
|---|---|---|---|
| 上部 | 論理テーブル名 | テーブルの論理名称を記述する。 | 企業 |
| 上部 | 物理テーブル名 | テーブルの物理名称を記述する。 | `COMPANY_MST` |
| 上部 | テーブル説明 | テーブルに関する説明を記述する。 | 「システムに登録するユーザが所属する企業の情報」 |
| 明細行 | No. | （通し番号。凡例に明記無いが実務上は行順） | 1, 2, 3... |
| 明細行 | 論理名称 | カラムの論理名称を記述する。 | 企業コード |
| 明細行 | 物理名称 | カラムの物理名称を記述する。 | `COMP_CODE` |
| 明細行 | ドメイン名 | カラムの論理名に紐付くドメイン名を記述する。**ドメイン定義書で定義した値を引用する。** | 企業コード |
| 明細行 | データ型 | カラムのデータ型を記述する。（プルダウンあり。下記の不整合を参照） | `NCHAR` |
| 明細行 | 桁数 | カラムの桁数を記述する。 | 5 |
| 明細行 | PK | 本テーブルのプライマリキーを、**1,2のように順に定義する**（○×ではなく、複合キーの場合の並び順を数字で書く）。 | `1`（単一列PKの場合） |
| 明細行 | 必須 | 必須項目には「○」、必須項目でない場合は「×」を記述する。 | ○ |
| 明細行 | INDEX | INDEX情報を記述する。**記載方法はテンプレートのINDEX見出しセルに付いているExcelコメントを参照**（下記「INDEXの書き方」を参照）。 | （下記参照） |
| 明細行 | 項目定義 | 項目の意味を記述する。 | 「企業を一意に識別するコード。FWの採番機能を利用して採番したユニークなキー」 |
| 明細行 | 初期値 | 初期値を設定する場合に初期値を記述する。 | （無ければ空欄） |
| 明細行 | 暗号化対象 | 暗号化対象の項目の場合は「○」、暗号化対象でない項目の場合は「×」を記述する。 | × |
| 明細行 | 備考 | **NOT NULL制約・ユニークキーインデックスの制約"以外"の制約**について記述する。値範囲（正・負）、単位（円、10のn乗など）について記述する。 | （該当する場合のみ） |

## INDEXの書き方（確定・INDEX見出しセルのExcelコメント原文より）

INDEX列は1〜7の番号を持つ7つのサブ列に分かれており、**サブ列の番号＝定義するインデックスの番号（インデックス1〜インデックス7）**を表す。7を超えるインデックスが必要な場合は列を追加する。

各インデックス（サブ列）につき、**2種類の情報を別々の行に記入する**。

1. **タイトル行**（そのインデックス列の一番上、データ行より前）：インデックスの**種別**を記述する。
2. **各項目行**（実際のカラムがそのインデックスに属する場合）：**付与順**（上段）と**昇順/降順**（下段）を記述する。

### インデックス種別（タイトル行に記述する記号）

| 記号 | 意味 |
|---|---|
| `U` | ユニークインデックス |
| `R` | 逆キーインデックス |
| `B` | ビットマップインデックス |
| `C` | クラスターインデックス |
| `UR` 等の組み合わせ | 例：ユニークな逆キーインデックスなら`UR`のように併記する |

※RDBMSによっては存在しない種別・組み合わせ不可の種別がある。**各プロジェクトで使用するRDBMSに応じてカスタマイズして使用すること**（本プロジェクトはPostgreSQLのため、Oracle前提の種別がすべて使えるとは限らない点に注意）。

### 各項目行の記述（付与順・昇順/降順）

その列がインデックスを構成しない場合は空欄のまま。構成する場合は、該当するインデックスのサブ列に上下2段で記入する。

- 上段：そのインデックス内での**付与順**（1, 2, 3...）
- 下段：`A`＝昇順、`D`＝降順

### 記述例（Excelコメント原文の例をそのまま引用）

あるインデックス（1つのサブ列）に対して、5つのカラムのうち3つが参加する場合：

| 物理名称 | INDEX（該当サブ列） |
|---|---|
| 項目1 | 上段=`2`、下段=`D`（2番目・降順） |
| 項目2 | （空欄＝このインデックスに含まれない） |
| 項目3 | 上段=`1`、下段=`A`（1番目・昇順） |
| 項目4 | （空欄） |
| 項目5 | 上段=`3`、下段=`A`（3番目・昇順） |

→ このインデックスは「項目3（昇順）→項目1（降順）→項目5（昇順）」の順に構成される複合インデックス、という意味になる。

### 記入時の注意

- 1つのカラムが複数のインデックスに属することもある（例：企業テーブルのサンプルでは、略式コードがINDEX1とINDEX2の両方に登場する）。
- タイトル行（種別）と各項目行（付与順/昇順降順）は**別の行**に書く。1つのセルに両方を混在させない。
- 使用しないインデックス番号の列は空欄のままでよい（7つすべて埋める必要はない）。

## シート『データ』について

このシートはプルダウン用の選択肢リスト（データ型の一覧）を保持するための裏方シートであり、直接編集しない。
**ただし下記の不整合解消でOracle型からPostgreSQL型に切り替える場合は、このシートのA列を書き換える必要がある。**

## 記入時のポイント

- 「ドメイン名」列は自由記述にせず、必ずドメイン定義書に存在する名称から選ぶ。存在しなければ先にドメイン定義書へ追加する（型・桁の二重管理を防ぐため）。
- 「PK」は○×ではなく、複合主キーの並び順を表す**数字**で記入する（単一列なら`1`のみ）。
- 「備考」に書くのはNOT NULL制約・ユニークインデックス制約"以外"の制約（値範囲、単位等）。NOT NULL自体は「必須」列で表現済みのため重複記載しない。
- 物理名称の命名規則（大文字＋アンダースコア等）はDB設計標準に従う。
- 列の追加は構造を崩すリスクがあるため、既存の列構成で足りない場合は追加前に構造メモを確認し、事前に相談すること。

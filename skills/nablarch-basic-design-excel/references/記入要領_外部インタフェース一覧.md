# 記入要領: 外部インタフェース一覧

## 資料の目的

対象サブシステムが外部（他システム・他サブシステム）とやり取りするファイル・電文の一覧を定義する。
**ファイル連携（バッチ間I/F等）が存在する場合に作成する**資料。
純粋なWeb API公開のみのシステム（B1顧客管理システムのようなケース）では、外部との連携がAPI経由のみであれば、この資料の代わりに「WebサービスAPI一覧」で管理し、本資料は不要になることが多い。
項目数は全13項目（下表参照）。

## どこに何を書くか（シート『1』、見出しは7〜8行目）

| 項目名 | 記入内容 | 記入例（A1プロジェクト管理システム） |
|---|---|---|
| No. | 通し番号 | 1, 2, 3 |
| ファイルID/電文ID | ファイル連携ならファイルID、電文ならレコードID | `N21AA001`, `N21AA002` |
| 外部インタフェース名 | インタフェースの名称 | 登録用プロジェクト一覧、期間内プロジェクト一覧 |
| 入出力種別 | 「入力」または「出力」（自システムから見て）※プルダウン：`入力,出力` | 出力、入力 |
| 相手先 | 連携先のシステム名（未定なら「-」） | - |
| 媒体 | インタフェースの授受媒体を記載する。**「JSON、XML」の場合は「-」と記載する**（Excelセルコメントより） | FTP、共有ディレクトリ 等 |
| 授受方式 | 伝送の場合は伝送方式、その他の場合は媒体送付方法を記載する（例1：伝送ファイルの場合「FTP」または「HULFT」／例2：MT/FD/MOの場合「オフラインMTサーバ」） | プッシュ／プル、バッチ転送 等（プロジェクトで定義） |
| 暗号化有無 | ※プルダウン：`有り,無し` | 無し |
| 文字コード | ファイルの文字コード | UTF-8、Shift_JIS 等 |
| 処理サイクル（サイクル／詳細） | サイクルは「日次」「週次」「月次」「年次」「随時」「その他」のいずれか。詳細には、サイクルに記載されたタイミングのうちどのタイミングで実行するかを記載する（例：毎週月曜10:00） | サイクル＝日次、詳細＝毎日0:00起動 |
| データ量（ﾚｺｰﾄﾞ長／件数(ピーク時件数)） | レコード長：固定長ならバイト数、可変長なら最大バイト数。**「JSON、XML」の場合は「-」**。件数：データレコードの行数。固定長など改行の無いIFはレコード長で区切った件数、**「JSON、XML」の場合は行数ではなく論理的なデータ件数**を記載する（いずれもExcelセルコメントより） | （プロジェクトの見積りに基づき記載） |
| ファイル保存期間(日数) | 生成後、何日間ファイルを保持するか | 30 |
| 備考 | 補足事項 | - |

## 記入時のポイント

- ここで採番した「ファイルID/電文ID」が、対応する「外部インタフェース設計書」のファイル名・取引IDと一致している必要がある。
- 入出力種別は自システム基準（自システムが送り出すなら「出力」、受け取るなら「入力」）で統一する。
- API連携（JSON電文）の場合、この一覧とは別に「WebサービスAPI一覧」でも管理されるため、二重管理にならないよう役割を分ける（本一覧はファイル/電文ベースの連携、WebサービスAPI一覧はAPIエンドポイントベースの一覧）。
- 「処理サイクル」「データ量」は、外部インタフェース設計書(JSON)側にも類似項目（処理サイクル、レコード長）があるため、両方に矛盾なく記載する。

# 記入要領: システム機能一覧

## 資料の目的

対象サブシステムが持つ業務機能を一覧化し、機能ID・機能名・機能説明を採番・定義する。
Must4の中で**最初に確定させるべき**資料。ここで採番した機能IDが、以降のすべての設計書（機能設計書・URL一覧・システム処理フロー等）のキーになる。

## どこに何を書くか（シート『1』）

見出し行（7〜8行目、以下すべて）：`No. / 機能ID / 機能名 / 機能説明 / 取引ID / 取引名 / 取引説明 / 処理方式 / 備考`
**機能一覧ではなく「機能一覧＋取引一覧」を兼ねた表**になっている。

| 位置 | 項目名 | 記入内容 | 記入例（A1プロジェクト管理システム） |
|---|---|---|---|
| 1〜3行目 | PJ名／システム名／サブシステム名 | ドキュメント共通ヘッダー | サンプルプロジェクト／サンプルシステム／プロジェクト管理システム |
| データ行 | No. | 通し番号 | 1, 2, 3... |
| データ行 | 機能ID | 機能の識別ID（採番規則はプロジェクトで統一） | `A101`, `A102` |
| データ行 | 機能名 | 機能のまとまりの名称（体言止め） | ログイン、プロジェクト管理 |
| データ行 | 機能説明 | 機能が何をするかを1〜2文で説明 | 「プロジェクトを管理対象として登録し、そのデータの更新や参照、削除を行う。」 |
| データ行 | 取引ID | 機能の中の個々の取引（画面/バッチ/API）のID。システム機能設計書の取引IDと一致させる | `A10201`（プロジェクト登録） |
| データ行 | 取引名 | 取引の名称 | プロジェクト登録 |
| データ行 | 取引説明 | 取引が何をするかの説明 | 「新規プロジェクトを登録する。」 |
| データ行 | 処理方式 | 入力処理方式の名称を記入する（詳細は方式設計書側に書き、ここには記述しない）。画面・ディレード処理方式など、ディレード処理を起動する取引とディレード処理自体の取引が分かれる場合は、**起動する取引には「画面・ディレード」、ディレード処理の取引には「常駐バッチ」と記入する**（Excelセルコメントより） | 画面 |
| データ行 | 備考 | 補足事項（無ければ空欄） | - |

## 表の構造上の注意

「機能」1行に対して「取引」が複数ぶら下がる場合（例：プロジェクト管理機能に登録・照会・更新の3取引がある場合）は、機能ID/機能名/機能説明を持つ行の下に、取引ID以降だけを変えた行を追加する形になる（機能ID列は空欄または結合して表現する場合がある。既存の結合セル構成を崩さないよう、構造メモを確認しながら追記すること）。

## 記入時のポイント

- **粒度**：1機能ID＝1つの業務のまとまり（例：「プロジェクト管理」）であり、個々の画面やAPI単位ではない。個々の処理（顧客検索・顧客登録等）は後続の「システム機能設計書」「WebサービスAPI一覧」側でIDを振る。
- 機能IDの採番規則を最初に決めておく（例：サブシステムを表す英字1〜2桁＋連番3桁）。
- ここで確定したIDと名称は、以降の全設計書で**表記を完全に一致させる**（表記ゆれがあると資料間のトレーサビリティが崩れる）。

# 記入要領: システム機能設計書(バッチ)

## 資料の目的

1つのバッチ取引について、起動パラメータ・処理内容・入出力・終了コード・処理詳細（ロジック）・出力データの編集仕様までを定義する。
**バッチ取引につき1ファイル**作成する。1つの取引の中に複数のバッチ処理（ステップ）がある場合は、シート『2』を処理数分コピーする。
※B1顧客管理システムのようにバッチを持たないシステムでは、この資料は不要（Must4の対象外にできる）。

## シート『1.1. バッチ取引概要』

| 位置（行） | 項目名 | 記入内容 |
|---|---|---|
| 8行目 | 取引ID | バッチ取引の識別ID（例：`BA10601`） |
| 9行目 | 取引名 | バッチの名称（例：期間内プロジェクト一覧出力バッチ） |
| 10〜29行目（結合） | 取引概要 | バッチが何をするかの説明文 |
| 30〜33行目（結合） | 起動条件 | いつ・何をトリガに起動するか（例：日次バッチとして深夜0時に起動） |
| 34〜41行目（結合） | 前提事項 | 起動前に満たされているべき条件（無ければ「なし。」） |

### 1.2. バッチ処理一覧（44〜59行目）

見出し：`No. / バッチ処理ID / 処理名 / 常駐 / 多重化要否(プロセス/スレッド) / 処理概要`

この取引が複数の処理ステップ（例：ワークテーブル登録→本テーブル登録）から成る場合、その一覧をここに記載する。
常駐バッチかどうか、多重実行を許容するかをプロセス単位・スレッド単位で記載する。
**「常駐」は常駐バッチの場合「○」を記入する。「多重化要否」はプロセス・スレッドそれぞれ、必要な場合「○」、不要な場合「-」を記入する**（Excelセルコメントより）。

## シート『2. [バッチ処理ID]([バッチ処理名])』

### 2.1. 処理概要（8〜10行目）

`処理単位 / 処理順序 / リカバリ方法`

- 処理単位：処理の実施単位を記述する。
- 処理順序：入力データを処理する順番を記述する（例：ユーザ管理テーブル.ユーザIDの昇順）。キーが複数ある場合は優先順位の高いキーから順に左から並べる（例：契約テーブル.契約日の昇順＞契約テーブル.契約IDの昇順）。
- リカバリ方法：複雑な場合は別紙に記述する。

### 2.2. 起動パラメータ（13〜18行目）

見出し：`No. / パラメータ名 / 必須 / パラメータ値 / 説明 / パラメータ名(物理)`

起動時に渡すパラメータを列挙する。**システム共通の起動パラメータ以外に必要なパラメータがある場合のみ記述する**（システム共通の起動パラメータの設定値は方式設計書側に書き、システム機能設計書には記述しない）。「パラメータ名(物理)」はプログラム内で使う実際の変数名。
「必須」は必須「○」、省略可「-」を記入する（省略したときの動作は「説明」欄に記述する）。
「パラメータ値」は設定可能な値を記述する。具体的な値がある場合は`[値]:[値の意味]`（例：`0:指定なし、1:指定あり`）、無い場合は`[設定値名]([書式])`（例：`請求日(yyyyMMdd)`）の形式で書く（いずれもExcelセルコメントより）。

### 2.3. 処理結果一覧（21〜26行目）

見出し：`No. / 終了コード / 障害コード / 処理結果`

正常・異常それぞれの終了コードと発生条件を記載する。

### 2.4. 入出力一覧（29〜35行目）

見出し：`No. / 入出力名 / 種別 / I/O / DBアクセス種別(C/R/U/D/ﾛｯｸ対象) / 備考`（Webサービス版と同じ形式）

**記載範囲（Excelセルコメントより）**：当バッチ処理で作成/参照/更新/削除を行う**全て**のテーブル/ファイル/電文/帳票/メールを記述する。バリデーションのために参照するテーブルも記述する。**当バッチ処理が呼び出す共通コンポーネントが使用するテーブル/ファイル/電文/帳票/メールは記述しない**（呼び出し先の内部実装まで一覧に含めない）。

### 2.5. 入力データ定義（38〜56行目）

対象（テーブル／ファイル・メール・電文）ごとに区切って記載する。

- 2.5.1. `[入力対象（テーブル名）]`：見出しを実際のテーブル名に変更した上で、
  - 「取得項目」表（`No./取得元/取得項目/必須/ドメイン名/備考`）：どのテーブルのどの項目を取得するか。**バリデーションのために取得・参照するデータはここに記述しない**（Excelセルコメントより）。
  - 「取得条件」：抽出条件（WHERE句に相当する条件）を自由記述。ファイルを全件読み込む場合等、特に無い場合は「-」と記述する。
- 2.5.2. `[入力対象（ファイル名/メール名/電文名）]`：「【外部インタフェース定義書_XXX】を参照。」の下に、ファイルID/メールID/電文IDのいずれか、およびファイル名/メール名/電文名のいずれかを記載する。

### 2.6. 処理詳細（59〜88行目）

`(1) [処理名称]` の形で処理をステップに分けて自由記述する広いエリア。実際の業務ロジック（集計方法、更新順序、トランザクション制御、異常時のロールバック方針等）を記述する。
**処理は目的（入力、各種業務処理、出力等）に分割して記載する**（Excelセルコメントより）。例：`(1) ○○バリデーション` `(2) ○○取得` `(3) ○○集計` `(4) ○○登録`

### 2.7. 出力データ定義（89〜124行目）

出力先の種類ごとに3パターンの書き方がある。

- 2.7.1. `[処理名(登録)]：[処理対象（テーブル名）]` — 新規登録する場合。`No./項目名/編集元（ファイル/テーブル名・項目名）/編集仕様/備考` の表で、登録する各カラムの値がどこから来てどう編集されるかを記載。
- 2.7.2. `[処理名(更新/削除)]：[処理対象（テーブル名）]` — 更新・削除する場合。「更新条件」を自由記述したうえで、同様の編集仕様表を記載。
- 2.7.3. `[処理名(出力)]：[処理対象（ファイル名/メール名/電文名）]` — ファイル・電文として出力する場合。「(1) 項目定義」で外部インタフェース定義書を参照指示し、「(2) 編集仕様」で `No./項目ID/項目名/編集元（ファイル/電文/テーブル・項目名）/編集仕様/備考` を記載。

同じバッチ処理の中で複数の出力先がある場合は、2.7.1〜2.7.3をそれぞれ複数回（2.7.1, 2.7.2...のように）繰り返す。

## 記入時のポイント

- 「2.4 入出力一覧」「2.5 入力データ定義」「2.7 出力データ定義」のテーブル名は、テーブル定義書の論理テーブル名と一致させる。
- 「2.6 処理詳細」「2.7 出力データ定義」は分量が多くなりがちで、調査・整理資料の記述が薄いと不明点が多く出る部分。
- ジョブ間の実行順序・依存関係そのものは、この設計書ではなく「ネット・ジョブフロー」（Must4の対象外）に記載する。

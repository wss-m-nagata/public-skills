# 打ち合わせ用Excelの作り方

Markdownで整理した内容から、打ち合わせ相手が読み、考えを書き込めるExcelブックを作る。
このスキル専用のテンプレートとスクリプトを使い、Nablarch様式を参考にした表紙・変更履歴・共通ヘッダーを持つブックを作る。

## 生成する

Windowsのデスクトップ版Microsoft ExcelとWindows PowerShellを使う。
[入力JSONの例](../assets/workbook-input.example.json)を参考に内容を用意する。
[生成スクリプト](../scripts/build-workbook.ps1)は、同梱の[空テンプレート](../assets/concept-workbook.xlsx)からブックを新規作成する。
レビュー中は、同じブックを同じ場所・ファイル名で更新する。記入や手修正を受けたブックは、そのファイルを土台に編集する。未記入の版を再生成した場合も、確認後に既存ファイルと差し替える。

```powershell
& '<スキル>/scripts/build-workbook.ps1' -InputJson '<入力.json>' -OutputWorkbook '<出力.xlsx>'
```

印刷プレビューの出力には `-PreviewPdf '<確認用.pdf>'` を付ける。

- `project`、`title`、`position`、`version` が表紙に入る。システム名とサブシステム名は、内容が分かる場合に `system`、`subsystem` を入れる。
- `history` に古い順に版を並べる。各行は `version`、`date`（YYYY-MM-DD）、`category`、`area`、`summary`、任意の `author` で構成する。末尾の版数を表紙とそろえる。
- `sheets` に「概要」「スコープ」「To-Be」「検討事項」の順で入れる。各シートに `intro`、`sections` を置く。章ごとの節には `number`、`title`、`blocks` を入れる。 表が長い場合は、ページを分けたい節に `pageBreakBefore: true` を指定する。
- 本文ブロックの `kind` は、見出し `label`、文章 `note`、表 `table`、スイムレーン `flow`、情報伝達図 `information-transfer` から選ぶ。
  見出しと文章には `text` を指定する。
- 表では `columns` に列見出し、`rows` に同じ列数の行を入れる。記入欄や合意欄の見出しは `responses` に追加する。表は記入欄も含めて７列まで。検討事項は「No.」「区分」「項目」「内容」の一つの表にまとめる。
- 観点名や業務名など、作成者側にも載せる記入の手掛かりは `prefillColumns` に `columns` の見出し名を指定する。
  指定した列だけ、記載例の値を左側にも表示する。No.は自動採番する。
- 図では `title`、`lanes`（担当２～５件）、`steps`（各行は［担当、短い作業内容］。As-Isで困りごとを図に添える場合は３番目に短い課題を書く）を入れる。ケースごとに図を分け、分岐や戻り先が多い場合は詳細を表で示す。

受け渡しや分岐を描く場合は、`steps` の代わりに `nodes` と `edges` を使う。工程は［ID、レーン名、０から始まる行、表示文、任意で `decision`］、矢印は［接続元ID、接続先ID、任意のラベル、任意で `left` または `right`］とする。表示文は意味の切れ目で改行する。上の工程へ戻る線は破線で表示する。戻り線や途中を飛ばす分岐は、工程と重ならない側に接続する。

同じ送り手から同じ受け手に複数の経路で情報が渡る場合は、情報伝達図を使える。
`title`、`entryTitle`、送り手 `source`、送り手の補足 `sourceDetail`、受け手 `recipient`、2～3件の `paths` を指定する。
各経路に情報の種類 `name`、情報の例 `examples`（短い文字列1～3件の配列）、現在の伝達方法 `method`、伝達の状況 `condition`、受け手の対応 `recipientAction` を入れる。
伝達が途切れる可能性がある経路の `interrupted` を `true` にすると、受け手の手前に「×」を表示する。
届く経路は `false` とし、矢印で表す。
情報の伝達を業務全体の流れの中で示す場合は、`workflow` を追加する。
`trigger` に業務の発生、`handover` と `handoverDetail` に引き渡しの見出しと概要、`receipt` に受け手が受領する状態、`actionsHeading` に受領後の作業の見出し、`resume` に作業後の到達点を書く。
この形式では、各経路の伝達状況を中央の引き渡し欄に示し、矢印は業務段階の移行に使う。

## レイアウトと確認

- 表紙と変更履歴の後に本文４シートを置く。本文の共通ヘッダーは変更履歴の値を参照する。変更履歴のタイトルと列見出しは塗りつぶさず、標準の太さにする。列見出しと最初の履歴データの境界に二重線を引く。
- 章の項番はB列、見出しはC列。節の項番はC列、見出しはD列。本文はE列から置く。節の下に小見出しを置く場合はE列、小見出しの本文はF列から置く。見出し付近の基本列幅は３にする。表は必要な列数をまとめて幅を確保する。節と節の間に空行を置き、同じ列でCtrl＋矢印キーを使って移動できるようにする。
- 本文の表は先頭にNo.を置き、シート内で重複しない通し番号を振る。セル内の文章は句点で改行する。章・節・小見出しに背景色を付けない。表の列見出しは淡いグレー、記入欄は淡いクリーム色、スイムレーンの工程は表と異なる淡い青にする。ウィンドウ枠は固定しない。
- As-Is図は現状の業務と判断を示す。課題は別の見出しに短くまとめ、必要に応じて図の工程と対応させる。スコープは対象の境界を短い表で示す。To-Beは目指す状態と流れを示し、担当の受け渡しはスイムレーン図に含める。詳細の工程表は、基本方針の判断に必要な場合だけ添える。検討事項は会議で方針を決めるための問いに絞る。
- 印刷範囲内は、共通ヘッダー・項目名と、作成者が書くための空欄を置く。提示側の記載例・仮説・図は、対応する行の右側にまとめ、印刷範囲に入れない。記載例を印刷する場合は、右側の必要なセル範囲を選び、Excelの印刷画面で「選択した部分を印刷」を使う。
- 保存後にExcelで開き直し、項番と本文の位置、共通ヘッダー、記入欄、図、印刷時の文字の収まりを確認する。印刷範囲は左側の記入欄と最終行までとし、本文は各シート１ページを目安にする。文字が小さくなる場合は、まず内容を絞る。確認相手に渡す成果物はExcelブックとする。

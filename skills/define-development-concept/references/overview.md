# 概要シートの記載要領

取り組みの必要性を共有し、何を解決したいかを合わせる。

- 冒頭に、会議の目的と資料の見る順序を書く。
  右側の記載例と左側の記入欄を案内する。
- 目的は、何を変えることでどのような状態を実現するかを書く。
  特定の製品や実装方法を選ぶ話は後工程で扱う。
- As-Isは方針を決めるために把握すべき現状を図にする。
  初めて読む人に業務の前提が伝わりにくい場合は、業務が発生するきっかけと現在の進め方を図の前に短く添える。
  情報の引き継ぎが主題の場合は、情報の種類、現在の受け渡し方、受け手が追加で行う確認や調査を示す。
  業務の流れを検討する場合は、情報を分類するだけでなく、業務の発生、引き渡し、受け手の作業、その後の状態までを示す。
  同じ送り手と受け手の間で情報の種類ごとに経路が異なる場合は、送り手と受け手をそれぞれ一つの枠にまとめ、種類と経路を間に並べる。
  手渡せる経路は矢印でつなぎ、伝達が途切れる可能性がある経路は「×」で示す。
  現状を確認できていない場合は、右側に記載例として置く。
- 課題はAs-Is図の下の別項目に書く。
  図には業務の流れを理解するのに必要な現状を残し、主要課題の説明は課題の節にまとめる。
  複数の課題が共通の問題につながる場合は、主要課題、個別課題、全体への影響が分かるように並べる。
  どこで何が起き、どのような影響があるかが分かるようにする。
  図の工程と関係する場合は対応を明示する。

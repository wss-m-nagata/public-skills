# 記入要領: 画面遷移図

## 資料の目的

1つの機能に属する画面の間の遷移を、1枚の図にする資料である。  
どの画面から、どのボタン・リンクで、どの画面へ移るかを示す。  
SPA では、ルートの切り替え（`router.push` など）を遷移として描く（読み替え）。  
サーバー描画の画面の場合は、画面を表示する Action のフォワード先を遷移として描く（原文のとおり）。

## どこに何を書くか

1機能＝1シートで作る。  
シート名と、シートの5行目の見出しは、`N. 機能名(機能ID)`（例：`1. 受注管理(11AA)`）にする。  
遷移図の本体は、見出しの下の空白の領域に描く。  
凡例（シート下部の図形）は、そのまま残す。

テンプレートには、凡例の図形があるだけで、図のための部品（箱・矢印）は用意されていない。  
このスキルでは、図を Graphviz（`dot`）で画像にしてシートに貼る。  
作業は `scripts/build_screen_flow.py` が行い、JSON で図の中身を渡す。

### 図の部品と、JSON の対応

| 図の部品 | 見た目 | JSON |
|---|---|---|
| トップ画面 | 黒丸。横に入口の名称を書く。 | `screens` の `kind: "top"` |
| 表示画面（メインウィンドウ） | 実線の箱。「画面名」と「【画面ID】」の2行。 | `kind: "main"` |
| 表示画面（サブウィンドウ） | 点線の箱。同上。 | `kind: "sub"` |
| 画面遷移 | 矢印。矢印の横に「ボタン／リンク名」を書く。 | `transitions` の `label` |
| 画面設計書の記載範囲 | 水色の角丸の枠。枠の見出しは「画面設計書ID／名」。 | `groups` と、画面の `group` |

SPA では、サブウィンドウは、別ウィンドウで開く画面や、モーダルダイアログとして独立して設計する画面に使う。  
画面設計書の記載範囲は、機能設計書を1冊にまとめる範囲（例：照会、登録、更新、削除）ごとに、枠で囲む。

### JSON の書き方

    {
      "functions": [
        {
          "function_id": "11AA",
          "function_name": "受注管理",
          "groups": [
            {"id": "SW11AA01", "name": "受注照会"}
          ],
          "screens": [
            {"id": "TOP1", "name": "受注一覧照会", "kind": "top"},
            {"id": "W11AA0101", "name": "受注一覧照会", "kind": "main", "group": "SW11AA01"},
            {"id": "W11AA0102", "name": "受注詳細", "kind": "main", "group": "SW11AA01"},
            {"id": "W91AA0101", "name": "顧客検索", "kind": "sub"}
          ],
          "transitions": [
            {"from": "TOP1", "to": "W11AA0101"},
            {"from": "W11AA0101", "to": "W11AA0102", "label": "受注番号"},
            {"from": "W11AA0102", "to": "W11AA0101", "label": "戻る"},
            {"from": "W11AA0101", "to": "W91AA0101", "label": "顧客検索"}
          ]
        }
      ]
    }

- `functions` の要素が、機能1件（1シート）である。機能が複数あるときは、要素を並べる。
- トップ画面の `id` は、遷移の `from` にだけ使う識別子であり、画面一覧の画面IDではない。`name` に入口の名称（メニュー名、URL の入口など）を書く。
- `screens` の `id`（トップ画面以外）は、画面一覧の画面IDと一致させる。
- `rankdir` は、図の向き（`LR`＝左から右、`TB`＝上から下）。省略すると `LR` になる。
- `nodesep`（箱どうしの間隔。既定 `0.3`）と `ranksep`（段どうしの間隔。既定 `0.65`）は、インチで指定する（省略可。範囲は 0.1〜3）。
- `groups[].id`（画面設計書ID）と `name` は、枠の見出しに「ID/名」の形で両方出る。  
  ID だけでは意味が伝わらないので、名前は、機能設計書の名称と同じにする。  
  採番の既定案は、`SW`＋機能ID＋連番2桁（例：`SW11AA01`、見出しは `SW11AA01/受注照会`）。  
  プロジェクトに画面設計書IDの規則があれば、それに従う。既定案を使ったときは、報告に「仮の採番」と書く。
- `anchor`（既定 `B7`）は画像を貼るセル、`source_anchor`（既定 `AL5`）は dot ソースを書く先頭のセルである。
- 仕様に無い値（`kind` の誤り、存在しない画面の参照など）は、補正せずエラーになる。

### 実行

    python scripts/build_screen_flow.py <テンプレートxlsx> <JSON> <出力xlsx> [--dot-out <dotソースの出力フォルダ>]

- 入力は、シート『1.  機能名 (機能ID)』を持つ、元のテンプレートにする。  
  図を作り直すときも、元のテンプレートから実行し直す。
- Graphviz の `dot` が PATH に必要である（無いときは `--dot` で指定する）。
- 図の中のフォントは、既定で `MS Gothic` である。別のフォントにするときは `--font` で指定する。
- 表紙・変更履歴の内容（PJ名、版数など）は、このスクリプトでは書かない。`apply_mapping.py` で書く。

スクリプトが自動で行うこと。
- 機能の数だけシートを作り（2件目以降はテンプレートのシートを複製）、『目次』に機能名を書く。
- 画像を、シートの drawing に直接貼る（凡例の図形と共存する）。
- 画像を、AI列までの幅と、1ページに収まる高さに縮小する。
- 画像が凡例に重なるときは、凡例を下へずらし、凡例の前で改ページする（凡例が2ページ目の先頭になる）。
- 印刷範囲を、A列から AI列、凡例の下端までに設定する。
- 画像の元の dot ソースを、`source_anchor` のセルから下へ書く（印刷範囲の外）。

## 記入時のポイント

- 1つの図に載せる画面は、10画面前後までにする。縮小率が55%を下回ると、スクリプトが警告を出す。そのときは、機能を分けるか、`rankdir` を `TB` にする。
- 遷移の矢印は、画面の中のボタン・リンクの操作だけを描く。API の呼び出しは、画面遷移ではないので描かない。
- 同じ画面に戻る遷移（検索など）は、`from` と `to` を同じ画面にして描く。
- 「戻る」「一覧へ」のような、ブラウザの戻る操作と区別がつかない遷移を描くかどうかは、プロジェクトで決めておく。
- 画面名・画面IDは、画面一覧と表記を完全に一致させる。
- 矢印のラベルが近い、矢印が枠の境界をかすめるときは、次の順に直す。
  1. JSON の `ranksep`（段どうしの間隔）を `0.65` から `1.0` 程度へ広げる。ラベルが矢印の途中で詰まるときに効く。
  2. JSON の `nodesep`（箱どうしの間隔）を `0.3` から `0.6` 程度へ広げる。同じ段の箱や枠が詰まるときに効く。
  3. `rankdir` を `LR` と `TB` で切り替えて、見やすいほうを選ぶ。
  4. それでも直らないときは、シートに残した dot ソースを手直しして、画像を作り直して貼り直す。  
     dot ソースを取り出して直し（`edge` に `[label="…", labelangle=…]` を足す、`nodesep` を直す、など）、`dot -Tpng -Gdpi=200 <dotファイル> -o <png>` で画像にして、Excel の既存の画像と差し替える。
  - 広げるほど図が大きくなり、縮小率が下がる。縮小率の警告が出たら、機能を分ける。

## 検証

このスクリプトの出力は、`scripts/verify_layout.py` の対象外である。  
`verify_layout.py` は、元のファイルと出力の構造を比べる。  
このスクリプトは、機能シートの名前を変え、シートを増やし、凡例の図形を新しい drawing に入れ直すので、次の3点が必ず差分として出る。
- シート構成が変化（機能シートの改名と複製）。
- 図形が失われたシート（元のテンプレートのシート名が無くなるため）。
- 図形の個数が増えたシート（凡例の図形と画像が、新しい機能シートに付くため）。

この3点は想定した変化なので、`verify_layout.py` が NG でも、異常ではない。  
この3点以外の差分（結合セル・背景色・入力規則・表紙の図形の変化など）が出たときは、異常として、原因を調べる。  
代わりに、次の3つで完了を確かめる。
1. スクリプトの終了コードが 0 であること。
2. 標準出力の警告（縮小率、重なりなど）を読み、対応したこと。
3. `scripts/export_sheet_preview.py` で、凡例が残っていて、図が凡例や枠に重なっていないことを、目で確認したこと。

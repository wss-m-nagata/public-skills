# 記入要領: メッセージ設計書

## 資料の目的

画面に出すメッセージ（入力エラー、確認、完了、警告など）を、メッセージIDと文言で管理する資料。  
メッセージIDごとに、メッセージの文言と、置き換える文字列の位置を定める。

### どんなときに作るか

この設計書は、プロジェクトによって要るかどうかが変わる。  
メッセージを**画面側（フロントエンド）で管理する**ときに作る。

- 画面側が、メッセージIDと文言を持つ（入力チェックのエラー、確認ダイアログ、完了通知など）。
- 画面側のメッセージを、関係者でレビューし、文言をそろえたい。
- 日本語以外の言語にも対応する。

次のときは、作らなくてよい。

- メッセージの文言を、すべてバックエンド（API）が返し、画面側は受け取った文言をそのまま表示する。
  この場合、メッセージの設計はバックエンド側の設計書が正で、フロントエンドは参照するだけである。

バックエンドが返すメッセージと、画面側で持つメッセージが混在するときは、画面側で持つものだけをこの設計書に書く。  
バックエンドのメッセージIDを、画面側の設計書から参照するときは、IDと文言をバックエンドの設計書から写さず、IDだけを書く（二重管理を避ける）。

### 読み替え（SPAの場合）

| 欄 | 原文の意味 | SPAでの読み替え |
|---|---|---|
| メッセージID | 画面・ログに出るメッセージのID | 画面側で持つメッセージのID。 |
| メッセージ内容 | 画面・ログに出力する文言 | 画面に表示する文言。入力チェックのエラー、確認、完了などを含む。 |

サーバー描画の場合は、原文のとおり（画面とログの両方に出るメッセージ）に書く。

## どこに何を書くか（シート『ja』『en』『ch』）

シートは言語ごとに分かれている（`ja`＝日本語、`en`＝英語、`ch`＝中国語）。  
3つのシートは同じ構造である。  
1〜3行目のPJ名・システム名・サブシステム名は、`変更履歴`シートを参照する数式のため、書かない（`記入要領_共通シート.md`を参照）。

見出しは7行目、データは8行目から23行目までの16行である。

| 列 | 項目名 | 記入内容 | 記入例（受注管理システム） |
|---|---|---|---|
| C | No. | 通し番号。 | 1, 2, 3 |
| D（D:H結合） | メッセージID | プロジェクトで定めた採番ルールに沿ったメッセージID。全言語のシートで同じIDにする。 | `E.ORD.0001` |
| I（I:AC結合） | メッセージ内容 | 画面に出す文言。置き換える文字列は`{0}`、`{1}`のように、波括弧で数字を囲む。数字は0からの連番にする。 | `{0}は必ず入力してください。` |
| AD（AD:AH結合） | 備考 | 特記事項。使う場面（入力チェック、確認、完了など）を書くと探しやすい。無ければ空欄。 | 入力チェック（必須） |

記入例：

| メッセージID | メッセージ内容 | 備考 |
|---|---|---|
| `E.ORD.0001` | `{0}は必ず入力してください。` | 入力チェック（必須） |
| `E.ORD.0002` | `{0}は{1}文字以内で入力してください。` | 入力チェック（桁数） |
| `C.ORD.0001` | `受注を{0}件取り消します。よろしいですか。` | 確認 |
| `S.ORD.0001` | `受注番号{0}を登録しました。` | 完了 |

## 記入時のポイント

- メッセージIDの採番ルールは、先に決める。
  種別（エラー・確認・完了）が分かるIDにすると、探しやすい（上の例では、先頭の英字1文字で種別を表している）。
- 置き換える文字列の番号（`{0}`、`{1}`）は、文言の中での出現順ではなく、呼び出し側が渡す引数の順に合わせる。
  どの引数が`{0}`になるかは、メッセージを使う側の設計書（画面イベントの処理、共通コンポーネント設計書のエラー情報の「埋め込み文字列」）に書く。
- 項目名を言語ごとに切り替えるときは、項目名もメッセージとして登録する。
  IDは「フォームのモデル名.項目名」の形にする（例：`order.orderNo`）。  
  画面項目の定義の「項目名」と、表記をそろえる。
- 同じ文言を、複数のIDに重複して登録しない。
- 3つの言語シートで、メッセージIDの並びと件数をそろえる。
  言語ごとに変えるのは「メッセージ内容」だけである。
- 使わない言語のシートは、残すか消すかを`記入要領_共通シート.md`の「多言語シート型テンプレート」に従って決める。
- メッセージIDは、画面側の設計書（画面イベントの処理、共通コンポーネント設計書のエラー情報）から参照される。
  IDを変えたときは、参照している設計書も直す。

## 行が足りないとき

各言語シートに書けるのは16行までである。  
超えるときは、`scripts/extend_table_rows.py`で、最終データ行の書式を下へ複製する（行の挿入はしない）。  
表の下には何も無いため、この方法が使える。  
言語ごとに、別々に実行する。

```bash
# ja: 最終データ行は23、対象列はC〜AH。20行足す
python scripts/extend_table_rows.py <入力xlsx> ja 23 20 C AH <出力xlsx>
# en、ch も同じ（行数は各シートで同じにそろえる）
python scripts/extend_table_rows.py <出力xlsx> en 23 20 C AH <出力xlsx2>
```

- 増やした行には、値は入らない。値は`apply_mapping.py`で書く。
- 行を足すと、`verify_layout.py`は「行数・結合セル・罫線が増えた」と報告する。
  これは意図した変更であり、足した行以外に差分が無いことを確かめる。
- 印刷範囲は広がらない。印刷や PDF 化で下の行が切れるときは、Excelの[ページレイアウト]→[印刷範囲]で広げる。

## 長い文言を書くとき

メッセージ内容は、1行（12ポイント）に収まる長さを超えると、2行目以降が隠れる。  
長い文言を書いたあとは、`scripts/fit_row_heights.py`で行の高さを広げる。

```bash
python scripts/fit_row_heights.py <入力xlsx> <出力xlsx> --rows 8-30 --sheet ja
python scripts/verify_layout.py <書き込み前のxlsx> <出力xlsx> --allow-row-heights
```

## 値を書き込む手順

```bash
python scripts/apply_mapping.py <フォーマットのxlsx または 前の手順の出力> <マッピングJSON> <出力xlsx>
python scripts/verify_layout.py <書き込み前のxlsx> <書き込み後のxlsx>
```

マッピングJSONの例：

```json
{"sheets": {"ja": {"C8": 1, "D8": "E.ORD.0001", "I8": "{0}は必ず入力してください。", "AD8": "入力チェック（必須）"}}}
```

- 結合セルは、左上のセル（D・I・AD）を指定して書く。
- 値を書いたあと、`scripts/export_sheet_preview.py`で見た目を確かめる。

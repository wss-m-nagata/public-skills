# 前提条件・出典

このスキルの記入要領・判断根拠として使っている、前提と出典をまとめる。
スキルだけを別のプロジェクトへ移したときにも、元の裏付けを参照できるように、内容そのものをここに保持する。

## テンプレートの公式配布元

`assets/templates/原本/`・`assets/templates/サンプル/` は、Nablarch開発標準の公式リポジトリから取得したものである。

```
https://github.com/nablarch-development-standards/nablarch-development-standards/tree/main/030_設計ドキュメント
```

- ブランチは `main`。
- 取得日は 2026-11-06。
- テンプレート（原本）は、`010_フォーマット` の次のフォルダから取得した。

| 設計書 | 原本のフォルダ |
|---|---|
| 画面一覧、画面遷移図 | `040_画面設計` |
| システム機能設計書(画面)、リクエスト一覧 | `010_システム機能設計` |
| 単体テスト仕様書(画面)、単体テスト仕様書(共通コンポーネント) | `110_テスト仕様書` |
| コード設計書 | `080_コード設計` |
| メッセージ設計書 | `070_メッセージ設計` |
| 共通コンポーネント一覧、共通コンポーネント設計書 | `020_共通コンポーネント設計` |

- 記入例（サンプル）は、`020_サンプル` の同じ名前のフォルダから取得した。
- 設計書の体系（どの設計書が何の入力になるか、作成の粒度）は、`030_設計ドキュメント/Nablarch開発標準設計書一覧.xlsx` にある。
- ライセンスは、Fintan コンテンツ 使用許諾条項（https://fintan.jp/?page_id=201）に準拠している。
  このスキルの外へ配るときは、出典とライセンスを併記する。

原本が更新されたときは、上のフォルダから再取得して `assets/templates/原本/` を置き換え、`scripts/build_formats.py` で `フォーマット/` を作り直し、`scripts/extract_structure.py` で構造メモを作り直す。

## `フォーマット/` は、原本の表紙を作り直したもの

`assets/templates/フォーマット/` は、`assets/templates/原本/` の表紙を、`scripts/build_formats.py` でセルベースに作り直したものである。

- 原本の表紙は、プロジェクト名・成果物名・サブシステム名を、テキストボックス（図形）で描いている。
  図形は、openpyxl で保存すると消え、値も入れられない。
- そのため、表紙の主要情報を、セルに作り直した（J12・J14・J16・J19・J28・J30。詳細は `記入要領_共通シート.md`）。
- 「関係者外秘」「PJ関係者限り」の図形は残している。
- 画面遷移図の凡例の図形など、本体のシートにある図形も、そのまま残している。

**作成・更新の元ファイルには、必ず `フォーマット/` のテンプレートを使う。**
`原本/` と `サンプル/` は、読むだけで、元ファイルには使わない。
サンプルは、人が編集した図形が残っていて、元ファイルにすると、表紙が二重に表示されたり、古い表示が残ったりする。

## 画面系の設計書の位置づけ（Nablarch開発標準）

- Nablarch の設計書一覧には、「画面アプリケーションについては、設計者の利便性を考慮し、インタフェース設計とシステム機能設計を1つの設計書に記載する」とある。
  そのため、画面側には、インタフェースだけの設計書は無く、システム機能設計書(画面)の入出力一覧が、その役を持つ。
- 画面が呼ぶ API の契約（項目、型、エラー）は、バックエンド側の設計書（WebサービスAPI一覧、外部インタフェース設計書）が正である。
  フロントエンドの設計書は、API の項目を二重に定義せず、項目名で参照する。

## 前提としている画面の方式

- 主な対象は、シングルページアプリ（Vue / Nuxt、React など）である。
- Nablarch の画面設計は、サーバーで画面を作る方式（JSP、Action、リクエストID、セッション）を前提にしている。
  このスキルは、テンプレートの様式を保ったまま、書く内容の解釈を SPA に読み替える。
  読み替えの表は、`SKILL.md` にある。
- サーバー描画の画面の場合は、原本の意味のとおりに書く。

## Nablarch に無い独自様式

`画面共通部品設計書` は、Nablarch には無い、このプロジェクト独自の様式である。
`assets/templates/フォーマット/` と `サンプル/` にあるが、`原本/` には対応するファイルが無い。

- 土台は、`フォーマット/` の共通コンポーネント設計書である。
  表紙、変更履歴、ヘッダー帯、フォント、罫線、見出しの配色、印刷設定を、そこから引き継ぐ。
- 本体のシートは、`scripts/build_ui_component_design.py` が作る。
  テンプレートを直すときは、このスクリプトを直して、`フォーマット/` と `サンプル/` を作り直す。
- `原本/` が更新されて、`build_formats.py` で `フォーマット/` を作り直したときは、このスクリプトで、画面共通部品設計書も作り直す。

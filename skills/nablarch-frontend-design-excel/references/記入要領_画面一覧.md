# 記入要領: 画面一覧

## 資料の目的

対象サブシステムが持つ画面（SPA ではルート／ページ）を一覧にし、画面IDを採番する資料である。  
画面IDは、画面遷移図・機能設計書・単体テスト仕様書で画面を指すときのキーになる。  
機能（機能IDで表す業務のまとまり）ごとに、その機能に属する画面を並べる。

サーバーで画面を作る方式（JSP など）の場合も、書き方は同じである。  
SPA では、1画面＝1ルート（または1ページコンポーネント）として数える。  
モーダルやダイアログのように、ルートを持たない部品を独立した画面にするかどうかは、プロジェクトで決める（決め方は「記入時のポイント」を参照）。

## どこに何を書くか（シート『1』）

見出し行は7行目、データ行は8行目から27行目までの20行である。  
1〜3行目（PJ名・システム名・サブシステム名・成果物名・作成・変更）は、『変更履歴』シートの値を参照する数式なので、このシートには書かない。

| 位置 | 項目名 | 記入内容 | 記入例 |
|---|---|---|---|
| C列 | No. | 通し番号。 | 1, 2, 3 |
| D〜F列（結合） | 機能ID | 画面が属する機能のID。機能の最初の画面の行にだけ書き、同じ機能の2行目以降は空欄にする。 | `11AA` |
| G〜K列（結合） | 機能名 | 機能の名称。機能IDと同じ行に書く。 | 受注管理 |
| L〜N列（結合） | 画面ID | 画面のID。採番規則はプロジェクトで決める。 | `W11AA0101` |
| O〜S列（結合） | 画面名 | 画面の名称。画面に表示するタイトルと合わせる。 | 受注一覧照会 |
| T〜AH列（結合） | 説明 | その画面が何を表示し、何ができるかを、1〜2文で書く。 | 検索条件を入力し、条件に該当する受注の一覧を表示する。 |

## 記入時のポイント

- 機能ID・機能名は、システム機能一覧など、プロジェクトが機能の正とする一覧と、表記を完全に一致させる。
- 画面IDの採番規則は、プロジェクトで先に決めておく。決め方の例を示す。
  - 例1：画面を表す英字1桁（`W`）＋機能ID（4桁）＋連番（4桁）。`W11AA0101` は、機能 `11AA` の1番目の画面を表す。
  - 例2：機能の略称＋連番。`ORD-001` のように、ルートのパス（`/orders`）と1対1にする。
  - どの例でも、画面遷移図・機能設計書・テスト仕様書の画面IDと完全に一致させる。
- 採番規則が決まっておらず、ユーザーに質問もできないときの既定案は、次のとおりである。  
  機能ID＝サブシステムID＋連番2桁（例：`OR01`）。  
  画面ID＝`W`＋機能ID＋連番2〜4桁（例：`WOR010101`）。  
  サブウィンドウ（モーダルなど）も、別の画面として、同じ規則で採番する。  
  既定案を使ったときは、報告に「仮の採番」と書く。
- 画面とルートの対応（`/orders/:id` など）は、この一覧の「説明」に書かず、機能設計書に書く。
- モーダル・ダイアログ・タブの切り替えを画面として数えるかは、プロジェクトで決める。  
  独立して設計・テストする単位なら画面として採番し、親画面の一部なら親画面の機能設計書の中で書く。
- 1機能に属する画面は続けて並べる。機能が変わる行で、機能ID・機能名を書く。
- 画面名は、利用者が見る名称にする。コンポーネント名やファイル名にはしない。
- 説明は、画面の見た目の細部ではなく、目的と主な操作を書く。細部は機能設計書に書く。

## 行が足りないとき

テンプレートの記入可能行は20行である。  
超えるときは、最終データ行（27行目）の書式を下へ複製して、行を増やす。

    python scripts/extend_table_rows.py <元xlsx> 1 27 <追加する行数> C AH <出力xlsx>

- 引数は、シート名（`1`）、最終データ行（27）、追加する行数、対象列の開始（C）と終了（AH）、出力パスの順である。
- 表の下に別の表が無いことを確認してから実行する（このテンプレートは、表の下に何も置かれていない）。
- 実行後は、`scripts/verify_layout.py` で構造が壊れていないことを確認する。

## 参照ファイル

- 構造情報：`references/構造メモ_画面一覧.md`
- 行の増やし方：`scripts/extend_table_rows.py`

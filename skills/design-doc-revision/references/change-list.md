# 変更箇所一覧の決まり

レビュー担当者が、何が変わったかを、設計書を開かずに把握するための表である。  
設計書の変更は、**すべて**載せる（確認資料には、相手に判断・対応してもらうものだけを載せる）。  

## ファイル

- 置き場所：作業フォルダの `変更履歴/`。  
- 名前：`変更箇所一覧_YYYY-MM-DD_<件名>.xlsx`。  
- 作り方：`scripts/build_change_list.py` に、仕様 JSON を渡す。  

## 「変更箇所一覧」シート

| 列 | 書くこと |
|---|---|
| No. | 並べ替えたあとの通し番号（自動） |
| 確認 | `要確認`＝レビュー担当者に判断・対応してもらうことがある。`任意`＝無い（お時間があれば、ご確認ください） |
| 対象ファイル | 正本の中の相対パス（例：`<フォルダ>/<設計書>.xlsx`）。省略しない |
| シート／ページ | 直したシート。表紙と変更履歴は、`表紙／変更履歴` とまとめる |
| 箇所 | 行・項目・セル座標まで書く |
| 区分 | `追加`・`変更`・`削除` |
| 変更前 / 変更後 | 値や文言。追加は、変更前を `（なし）` |

- 要確認の行は、オレンジ。上に集まる（それぞれの中は、書いた順）。  
- 版数と変更履歴の行も、1行ずつ載せる（例：`第1.3版` → `第1.4版。変更履歴に今回の変更を追加した`）。  
- 変更後の欄に、確認資料のシート名を書くと、レビュー担当者が、確認資料へ移りやすい（例：確認資料の「確認① <論点>」のとおり）。  

## 「ファイル一覧」シート

ファイルごとに、ファイルサーバーでの扱いを書く（自動）。  

- 修正：レビューのため、置き場に修正版を置く。合意後に、正本の旧版を、同じフォルダの `old\` へ移し、修正版を上げる。  
- 新規：置き場に置く。合意後に、正本に新しく置く。  

## 仕様 JSON

`assets/examples/change_list.example.json` を参照。  
`recipient` は、凡例に書く確認先の呼び名（省略時は、設定の「レビュー担当者の呼び名」）。  
`folder_name` を書くと、「ファイル一覧」の配置先に、置き場のフォルダ名が入る。  
段階（区分）を使うときは、`server_root`（置き場の親フォルダ）と、`files` の各件の `dest`（合意後の反映先の説明）を書く。

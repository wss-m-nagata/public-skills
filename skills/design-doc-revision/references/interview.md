# 設定のための質問（初回だけ）

設定ファイル `.agents/config/design-doc-revision/settings.md` が無いときに、1回だけ、この手順を行う。  
結果は、`assets/settings.template.md` の形で保存する。  
次回からは、質問せずに、保存した設定を使う（規約・手順の中身は、毎回、設定に書いた場所から読む）。  

**方針：プロジェクトから読み取れるものは、自分で読んで確定する。聞くのは、読み取れないものだけにする。**  
**既定は、そのプロジェクトのハーネス（指示書・README・設計書の置き方を決めた文書・手順書・規約）である。まず、そこを見に行く。**  
**ハーネスと外れている点、ハーネスに無い点だけを、プロジェクト固有の項目として聞く。**  
**設定に書くのは、場所と名前だけである。規約・運用手順の中身は、写さない。**  

## 手順1　先に読んで確定するもの

質問の前に、次を調べて、設定に書く内容を確定する。  
確定できたものは、質問しない（結果だけを伝える）。  

| 確定するもの | 探す場所の例 |
|---|---|
| 設計書の正本の場所（ファイルサーバー・共有フォルダなど） | `AGENTS.md`・README、設計書の置き方を決めた文書、`docs/` |
| レビュー用の置き場の場所と、案件ごとのフォルダの付け方 | 同上。ファイルサーバー側の README・運用の文書 |
| 設計書のフォルダ構成（種類ごとのフォルダ） | 正本の場所の一覧（読み取りだけ）、設計書の置き方の文書 |
| 段階（区分）の有無と、区分ごとの置き場・反映先 | 設計書の置き方の文書。区分が無ければ、「なし」 |
| 設計書の種類ごとに使うスキル | プロジェクトのスキルの置き場（`.claude/skills/` など）。公開されている `nablarch-basic-design-excel`・`process-flow-diagram`・`feature-er-diagram-drawio` が既定 |
| 設計書を直したあとの進め方を決めた手順書 | `AGENTS.md`・README・`docs/` の運用の文書 |
| レビュー担当者の呼び名（確認先が社外のとき） | README、課題管理の運用の文書 |

- ファイルサーバーの中は、**読み取りだけ**にする（一覧を見るだけ。書き込まない）。  
- 読んでも見つからなかったものは、「このプロジェクトには無い」として、設定に書く。  
- 読んだ結果が複数ある（候補の場所が2つ以上ある、など）ときだけ、どれかを聞く。  
- 文書を見つけたら、その文書の最終更新（コミットID。リポジトリの外なら更新日時）を、設定の「読む文書」の表に書く。  

## 手順2　読み取れないときだけ聞くこと

| # | 質問 | 既定（答えが無いとき） |
|---|---|---|
| 1 | 設計書のルートと、正本の場所は、どこか（見つからなかったとき） | なし（スクリプトは動かない。場所が決まるまで、取得に進めない） |
| 2 | レビュー用の置き場の場所は、どこか。案件ごとのフォルダ名は、どう付けるか | なし（上げるスクリプトは作れない） |
| 3 | 段階（区分）はあるか。あれば、区分ごとの置き場と反映先は | なし（反映先は1つ） |
| 4 | 取得した設計書のうち、フォルダの構成を保って置くものはどれか | すべて保つ |
| 5 | レビュー担当者は誰か（呼び名） | 外部のレビュー担当者 |

## 手順3　既定を示して、差分だけ聞くこと

次は、既定を示したうえで、「変えたい点はありますか」と1問で聞く。  
変えると答えたものだけを、設定ファイルに書く。  

| 項目 | 既定 |
|---|---|
| 手元の作業フォルダ | `.agents/state/design-doc-revision`（Git に入れない） |
| 取得の記録ファイル名 | `取得の記録.json` |
| 設計書の種類ごとの使うスキル | `nablarch-basic-design-excel`・`process-flow-diagram`・`feature-er-diagram-drawio` |
| 設計書を直したあとの進め方 | なし（案内しない） |
| 変更履歴に必ず書く記載 | なし |
| 確認資料の要否の基準 | 変更箇所一覧に「要確認」の行が1つでもあれば作る |

## 手順4　追加の項目を聞くこと

最後に、必ず、次を聞く。  

> ここまでで足りない項目はありますか。
> このプロジェクトに固有の決まり（例：流す前に必ず確かめること、報告に必ず書くこと）があれば、教えてください。

- 追加で出たものは、設定ファイルの「追加の項目」に、そのまま書く。  
- 追加の項目は、手順（SKILL.md）の該当する箇所で、必ず読み、従う。  

## 手順5　保存して確認を取る

1. `.agents/config/design-doc-revision/settings.md` を作る（ディレクトリが無ければ作る）。  
2. 書いた内容を、ユーザーに見せて、確認を取る。  
   読んで確定した項目は、読んだ場所も添える。  
3. Git に入れるかどうかを、ユーザーに確かめる（チームで共有するため、入れることをお勧めする）。  
4. `.gitignore` に、`/.agents/state/design-doc-revision` が書いてあるかを確かめ、無ければ、書くことを提案する（手元の作業フォルダは、使い捨てで、Git に入れないため）。

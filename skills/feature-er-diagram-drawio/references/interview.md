# 設定のための質問（初回だけ）

設定ファイル `.agents/config/feature-er-diagram-drawio/settings.md` が無いときに、1回だけ、この手順を行う。  
結果は、`assets/settings.template.md` の形で保存する。  
次回からは、質問せずに、保存した設定を使う（文書の中身は、毎回、設定に書いた場所から読む）。  

**方針：既定は、そのプロジェクトのハーネス（`AGENTS.md`、README、規約・設計の手順書、`docs/` の資料、DDL の置き場の説明）である。まず、そこを読みに行く。**  
**プロジェクトから読み取れるものは、自分で読んで確定する。ハーネスと外れている点と、ハーネスに無い点だけを、プロジェクト固有の項目として聞く。**  
**設定に書くのは、文書の「場所」と、スクリプトに渡す値だけである。文書の中身は、写さない。**  

## 手順1　先に読んで確定するもの

質問の前に、次を調べて、設定に書く内容を確定する。  
確定できたものは、質問しない（結果だけを伝える）。  

| 確定するもの | 探す場所の例 |
|---|---|
| DDL のフォルダ | `AGENTS.md`・README の、ディレクトリ構成の説明。`db/`・`migrations/`・`sql/`・`schema/` など。`*.sql` の置き場 |
| DDL の書式（`CREATE TABLE IF NOT EXISTS スキーマ.テーブル (...)` を主とするか） | DDL の実物を数ファイル読む。違う書式なら、「DDL の照合をしない」候補にする（スクリプトは、この書式だけを読むため） |
| ALTER ファイルの名前の形 | DDL の置き場の説明、マイグレーションの規約、ファイル名の並び。ALTER を置かない運用なら「なし」 |
| 設計書の置き方・命名の決まり | `AGENTS.md`、`docs/` の規約（設計書・図の置き場、ファイル名の形） |
| 処理フロー図の置き場・読み方 | `docs/` の設計の資料。処理フロー図を描くスキル（例：`process-flow-diagram`）があるか |
| 載せるテーブルの出どころ | 設計書の手順書、API 一覧・外部インタフェース設計書の備考欄の使い方 |
| 図・設計書の置くときの決まり | 設計書の運用の文書、README。承認の手順、旧版の退避の決まり |
| drawio の実行ファイル | 既定のインストール先（Windows：`C:\Program Files\draw.io\draw.io.exe`、macOS：`/Applications/draw.io.app/Contents/MacOS/draw.io`）、`which drawio` |
| 作業用ファイルを Git に入れない指定 | `.gitignore` に `.agents/state/` があるか |

- 読んでも見つからなかったものは、「このプロジェクトには無い」として、設定に書く。  
- 読んだ結果が複数ある（DDL のフォルダ候補が2つ、など）ときだけ、どれかを聞く。  
- 文書を見つけたら、その文書の最終更新（コミットID。リポジトリの外なら更新日時）を、設定の「場所の表」に書く。  

## 手順2　読み取れないときだけ聞くこと

| # | 質問 | 既定（答えが無いとき） |
|---|---|---|
| 1 | DDL のフォルダは、どこか（見つからなかったとき）。DDL は無いか | DDL なし（DDL の照合をとばし、spec だけで作る） |
| 2 | ALTER TABLE を置くファイルがあるか。あれば、ファイル名の形（正規表現） | なし（ALTER TABLE は、読めない文として止める） |
| 3 | 図に載せるテーブルは、何から集めるか（決まりが文書に無いとき） | 処理フロー図に出てくるテーブル |
| 4 | 完成した図は、どこに置くか。置くときの決まりはあるか | 置き場所は、置くたびにユーザーに聞く |
| 5 | spec JSON を、チームで共有するか。共有するなら、どこに置くか | 共有しない（作業フォルダに置いたまま） |
| 6 | 共有の置き場に置くとき、機能ごとに1ファイルにまとめる決まりはあるか | なし |
| 7 | 図のファイル名の形（決まりが文書に無いとき） | `ER図_<件名>.drawio` |

## 手順3　既定を示して、差分だけ聞くこと

次は、既定を示したうえで、「変えたい点はありますか」と1問で聞く。  
変えると答えたものだけを、設定ファイルに書く。  

| 項目 | 既定 |
|---|---|
| 作業フォルダ | `.agents/state/feature-er-diagram-drawio/<件名>/`（使い捨て。Git に入れない） |
| 載せる列 | その機能が読み書きする列と、PK・FK・一意制約に関わる列だけ |
| 既にある図の扱い | 毎回、ユーザーに聞く（作り直すか、手で直すか） |

## 手順4　追加の項目を聞くこと

最後に、必ず、次を聞く。  

> ここまでで足りない項目はありますか。
> このプロジェクトに固有の決まり（例：図に必ず書くこと、置く前に必ず確かめること）があれば、教えてください。

- 追加で出たものは、設定ファイルの「追加の項目」に、そのまま書く。  
- 追加の項目は、手順（SKILL.md）の該当する箇所で、必ず読み、従う。  

## 手順5　保存して確認を取る

1. `.agents/config/feature-er-diagram-drawio/settings.md` を作る（ディレクトリが無ければ作る）。  
2. 書いた内容を、ユーザーに見せて、確認を取る。  
   読んで確定した項目は、読んだ場所も添える。  
3. Git に入れるかどうかを、ユーザーに確かめる（チームで共有するため、入れることをお勧めする）。  
4. `.gitignore` に `.agents/state/` が無ければ、追加するよう案内する（作業用ファイルを Git に入れないため）。自分では書き換えず、ユーザーが決める。

# 図の中身（spec JSON）の書き方

`scripts/build_feature_er.py` に渡す JSON の書き方である。  
見た目（色・書式・凡例・線の通り道）はスクリプトが決めるので、JSON には中身だけを書く。  

書き方の例は `assets/example_spec.json` にある（ECサイトを想定した架空の例。1ページと変更点の表）。  
この例は、`scripts/build_feature_er.py` で図が作れ、`scripts/validate_feature_er.py` を DDL なしで通る。  
DDL の照合（`--ddl-dir`）には、例のテーブルに合わせた DDL が要る（例の箱は、変更・新規・廃止の区分を含むため）。  

次のときは、図を作らずにエラーで止まる。  
書き間違いや決まりの抜けを、黙って通さないためである。  

- 知らないキーを書いた（どのページでも使わない箱も確かめる）。  
- 必須のキーが無い。  
- ページに「この図に載せていないもの」（scope）の注記が無い。  
- 自分自身への線、廃止の箱への線、ラベルの無い simplified の線がある。  
- 廃止の箱に `pos` を書いた（廃止の箱は下部の帯に自動で並べる）。  
- ページが20枚を超える（ページ番号の丸数字が⑳まで）。  
- 変更点の表（`changes`）の区分が、どのページの箱の区分とも合わない。変更のある箱が表に無い。  
- 箱の `width` が、見出しの物理名より狭い。  
- 決めた日・確認した日（「（YYYY-MM-DD 決定）」「（YYYY/MM/DD）」など）を、図のどこかに書いた（[rules.md](rules.md) の 7）。  
  年・月・日のそろった日付は、すぐ後ろに「時点」が続くもの（`lead` の「（YYYY-MM-DD 時点）」など）を除いて、すべてエラーになる。  

配置で自動では解けなかったことは、図を作ったうえで「警告」として表示する。  
生成スクリプトの終了コードは、0＝警告なし、1＝エラー（図を作らない）、2＝警告あり（図は作る）である。  

## 最上位

```json
{
  "entities": { "<箱のキー>": { ... }, ... },
  "pages": [ { ... }, ... ],
  "changes": { ... }
}
```

| キー | 必須 | 内容 |
| --- | --- | --- |
| `entities` | ○ | 箱の定義。全ページで共通に使う。 |
| `pages` | ○ | 「使うテーブル」のページ。並べた順に①②…と番号が付く。 |
| `changes` | | 最後のページ「凡例・現行DDLからの変更点」の中身。書いたときだけページができる。 |

## entities（箱）

```json
"order": {
  "table": "shop.order",
  "logical": "注文",
  "status": "changed",
  "pk": ["注文ID（order_id） PK"],
  "cols": ["顧客ID（customer_id） FK", "★ 値引額（discount_amount）← 今回追加", "✕ 備考（note）"]
}
```

| キー | 必須 | 内容 |
| --- | --- | --- |
| `table` | ○ | `スキーマ.物理名`。 |
| `logical` | ○ | 論理名。見出しの1行目になる。接頭辞（［変更］など）は書かない（`status` から付く）。 |
| `status` | ○ | `unchanged`（変更なし）・`changed`（変更）・`new`（新規）・`abolished`（廃止）。 |
| `pk` | ○ | 主キーの行。 |
| `cols` | | 主キー以外の行。書き方は [rules.md](rules.md) の 4.2。 |
| `width` | | 箱の幅（px）。省くと中身から見積もる。見出しの物理名より狭くはできない（物理名が途中で切れるため、エラーになる）。 |
| `pos` | | `[x, y]`。省くと自動で並べる。指定すると、その座標にそのまま置く（説明・凡例の下へのずらしもしない）。廃止の箱には書けない。 |

箱のキーは、ページの `groups`・`edges` から指す名前である。  
DDLから下書きを作ると、物理名（スキーマ無し）がキーになる。  

## pages（使うテーブルのページ）

| キー | 必須 | 内容 |
| --- | --- | --- |
| `subject` | ○ | 主題。ページ名 `①使うテーブル（<主題>）` と見出し `① <主題>で使うテーブル` になる。 |
| `description` | ○ | 説明の行（配列）。箱の並べ方と、読む前提を書く。 |
| `auto_description` | | 既定は true。説明の最後に「箱の色は…凡例はページ右上。」を自動で足す。 |
| `layout` | | `columns`（既定。`groups` の1つが1列で、列の中は上から下へ積み、列を左から右へ並べる）か `rows`（`groups` の1つが1段で、段の中は左から右へ並べ、段を上から下へ積む）。既定の意味は [rules.md](rules.md) の 5。 |
| `groups` | ○ | 段（または列）の並び。`{"label": "商品（catalog）", "entities": ["product"]}`。`label` は省ける。 |
| `overrides` | | このページだけ箱の中身を変える。`{"customer": {"cols": [...]}}`。同じテーブルでもページによって載せる列が違うときに使う。 |
| `edges` | | 線。下の表。 |
| `notes` | | 注記。下の表。 |
| `legend_extra` | | 凡例の説明に足す行。 |

### edges（線）

```json
{"from": "order", "to": "order_coupon", "kind": "zero_to_one", "label": "1:0..1（UNIQUE）ON DELETE CASCADE"}
```

| キー | 必須 | 内容 |
| --- | --- | --- |
| `from` | ○ | 親（参照される側）の箱。 |
| `to` | ○ | 子（FKを持つ側）の箱。 |
| `kind` | | `fk`（既定。1対多）・`zero_to_one`（外部キー＋一意制約。1対0..1）・`one_to_one`（子が必ずある1対1）・`value`（値のみ保持、点線）・`simplified`（簡略化、点線。`label` 必須）。使い分けは [rules.md](rules.md) の 6。 |
| `label` | | 線に添える文字。省くと種類ごとの既定（`zero_to_one` は `1:0..1（UNIQUE）`、`one_to_one` は `1:1（UNIQUE）`、`value` は `値のみ保持`）。 |
| `exit` / `entry` | | 出入り口を `[x, y]`（箱の幅・高さに対する 0〜1）で指定する。省くと自動。 |
| `points` | | 折れ点を `[[x, y], ...]`（ページ上の座標）で指定する。省くと自動。 |

廃止の箱には線を引けない（エラーになる）。  

線の通り道は、自動で決まる（`scripts/router.py`）。  
読みにくいときだけ `exit`・`entry`・`points` で直す。  

- 箱と区分見出しを障害物とし、箱の周りに引いた縦横の候補線の上で、「長さ＋曲がる回数＋ほかの線との重なり」が最小の経路を探す。  
  並べ方や箱の組み合わせに関係なく、箱を横切らない経路を選ぶ。  
- 出る辺・入る辺は、候補の組み合わせ（横どうし、上下、下どうし など）を見積もって選ぶ。  
  同じ辺に付く線は、相手の位置の順に辺の上へ散らす。  
- ほかの線と同じ線上に重なるときは、出入り口を少しずらすか、別の辺の組み合わせで探し直す。  
- それでも重なる・見つからない・ラベルが置けないときは、段・列の間隔を広げて並べ直す（最大6回）。  
  解けなければ警告を出す。  

### notes（注記）

```json
{"kind": "scope", "title": "この図に載せていないもの", "lines": ["・shop.shipment（出荷）… 注文の登録では読まない。"]}
```

| キー | 必須 | 内容 |
| --- | --- | --- |
| `kind` | ○ | `point`・`readonly`・`scope`・`key`・`tbd`。使い分けは [rules.md](rules.md) の 7。`scope` は各ページに必ず1つ書く（載せないものが無ければ「・なし」と書く）。`tbd` の `title` は「T.B.D　〇〇に確認」で始める。 |
| `ai` | | `tbd` にだけ書ける。既定は true で、末尾に「AIの自動生成です」の定型文を付ける。人が書いた T.B.D は false にする。 |
| `title` | ○ | 見出し（太字）。 |
| `lines` | | 本文の行。`**…**` で囲んだ部分は太字になる。 |
| `width` | | 幅（既定 820px）。高さは文字数から見積もる。 |
| `pos` | | `[x, y]`。省くと、箱の下に左から右へ折り返して並べる。 |

## changes（変更点の表のページ）

```json
"changes": {
  "lead": "対象はDDLフォルダの現行ファイルである（YYYY-MM-DD 時点）。",
  "rows": [
    {"file": "020_shop_create_order.sql", "table": "shop.order", "kind": "変更",
     "lines": ["値引額（discount_amount）を追加する。", "クーポン適用時に、合計金額から引く額を持つため。"]}
  ]
}
```

| キー | 必須 | 内容 |
| --- | --- | --- |
| `lead` | ○ | 表の上に書く1文。基準にしたDDL（または設計書）を書く。日付を添えるときは「（YYYY-MM-DD 時点）」の形にする（「時点」が続く日付だけが許される）。 |
| `schema_owner` | | 「スキーマの持ち主」の行（配列）。省くと、その行は置かない。 |
| `rows[].file` | | DDLのファイル名。新規テーブルは空でよい。 |
| `rows[].table` | ○ | `スキーマ.物理名`。1つのファイルから2つのテーブルに分けるときなどは、配列で複数行を書ける（例：`["shop.order_history", "→ shop.order_log / shop.order_audit"]`）。 |
| `rows[].kind` | ○ | `変更`・`新規`・`廃止`・`変更なし`・`対象外`。 |
| `rows[].lines` | ○ | 変更内容の行。理由も書く。 |

# ヒアリングとルールファイルの作成

プロジェクト固有のルールが `.agents/state/process-flow-diagram/rules/` に無いとき、
1回だけこの手順を通してルールを作る。以降の作図では、そのルールを読むだけで済む。

質問はできるだけ少なくする。答えるのは人の時間を使う作業であり、
インプットから機械的に拾えるものを聞くのは無駄だからである。

## 手順

### 手順1　拾えるものを先に集める

質問する前に、インプットから次を集めておく。
そのうえで「この一覧で合っていますか。和名を教えてください」と聞けば、質問が1回で済む。

| 集めるもの | 探す場所の例 |
| --- | --- |
| テーブルの物理名・スキーマ | DDL（`db/migrations/` 等）、ER図、テーブル定義書 |
| 画面の一覧 | 画面のソース（`pages/`、`views/` 等）、画面一覧表、画面遷移図 |
| 処理の一覧 | ハンドラのソース、API 定義、インフラ定義（CDK/SAM/Terraform） |
| ファイル入出力 | バッチのソース、連携仕様書 |

インプットが要件定義だけで、これらがまだ存在しない場合は、一覧そのものをヒアリングする。

### 手順2　必ず聞くこと

| # | 質問 | 補足 |
| --- | --- | --- |
| 1 | **インプットは何か** | ソースコード／要件定義・設計書／両方。コードがあるなら、コードを正としてよいか |
| 2 | **対象範囲** | どの機能・どの工程か。どこからどこまでを1枚にするか |
| 3 | **As-Is か To-Be か** | コードがある場合のみ。ドキュメントだけなら聞かない |
| 4 | **システム構成** | 画面／処理の実行基盤（Lambda・コンテナ等）／データストア |
| 5 | **スキーマの和名** | 例：`survey` → アンケート実施スキーマ |
| 6 | **テーブルの和名** | 手順1で集めた物理名の一覧を見せて、和名を埋めてもらう |
| 7 | **画面の呼び方** | 手順1で集めた一覧を見せて確認する |

### 手順3　見た目は既定を提示して差分だけ聞く

見た目のルールは1問にまとめる。

> 図の見た目は既定のルール（`references/default_rules.md`）で進めます。
> 左から右へ読む3段構成、書き込みは緑の下向き、読み取りは青の上向き、
> 未確定事項は赤い破線の T.B.D 枠、といった形です。変更したい点はありますか。

変更が出たものだけを `extension_rule.md` に書く。
既定と同じ内容を書き写すと、既定を直したときに食い違うので書かない。

### 手順4　ルールファイルを書く

`.agents/state/process-flow-diagram/rules/` に2つ作る。
更新の頻度が違うので分けている。和名はテーブルが増えるたびに増え、描き方はめったに変わらない。

---

## `extension_rule.md` のテンプレート

```markdown
# 処理フロー図　プロジェクト固有ルール

`.claude/skills/process-flow-diagram/references/default_rules.md` を既定とし、
ここには**差分だけ**を書く。既定と同じ内容は書かない。

## インプットと前提

- インプット: <ソースコード / 要件定義 / 両方。優先するもの>
- 描き方: <As-Is / To-Be>
- システム構成: 画面=<>, 処理=<>, データストア=<>

## 対象範囲の切り方

- この図で扱う範囲: <機能名や工程名。作業計画があればその項目名>
- 範囲外として打ち切る箇所と、その行き先: <別の図の名前・工程の名前など、読み手が次に見るもの>

## 既定から変更する点

<無ければ「なし」と書く>

## 用語

| 図での呼び方 | 補足 |
| --- | --- |
| | |
```

## `naming.md` のテンプレート

```markdown
# 処理フロー図　和名の対応

図の中では和名を使う。ここは和名と実物の対応表である。
テーブルを追加したときは、ここも更新する。

## スキーマ

| 和名 | 物理名 |
| --- | --- |
| アンケート実施スキーマ | survey |
| 共通データ基盤スキーマ | common |

## テーブル

| 和名 | 物理名 |

## 画面

| --- | --- |
| | |

## 処理

| 図での呼び方 | 実装 |
```

## 2回目以降

ルールファイルがあれば、聞くのは1つだけでよい。

> 今回はどの操作を描きますか。（新規作成、複製、削除…）

ルールに書かれていないこと（新しいテーブルの和名など）が出てきたら、
そのときだけ聞いて `naming.md` に追記する。

# drawio_builder の使い方

`scripts/drawio_builder.py` は、処理フロー図を「画面」「処理」「テーブル」という図の語彙で
書けるようにしたライブラリである。drawio の XML を直接書くと、座標のずれ・ID の重複・
エスケープ漏れで壊れやすいため、生成は必ずこれを通す。

## 最小の例

```python
import sys
sys.path.insert(0, r"<スキルのパス>/scripts")
from drawio_builder import Diagram, Y_SCREEN, Y_LAMBDA, Y_TABLE, Y_NOTE

d = Diagram(page_w=2900, page_h=1100)

p = d.page("①新規作成")
p.title("① アンケート作成　新規作成の流れ（左から右へ読む）")
p.aws_frame("AWS（本システム）", 40, 70, 2800, 900)

actor = p.actor("システム管理者", 70, Y_SCREEN + 8)
scr = p.screen("アンケート一覧画面", 150, Y_SCREEN)
lmb = p.lambda_box("下書きを1件作る", 370, Y_SCREEN + 6)
out, _, _ = p.tables(["アンケート配信設定", "選択肢セット"], 430, Y_TABLE, "書き込み先", kind="out")

p.flow(actor, scr, "起動")
p.flow(scr, lmb, "① 新規作成を押す")
p.write(lmb, out, "② 追加")
p.back(lmb, scr, "③ 採番されたIDを返す")

d.save("処理フロー_xxx.drawio")
```

## Diagram

| メソッド | 用途 |
| --- | --- |
| `Diagram(page_w, page_h)` | ページの大きさを決める。横長になるので幅は広めに取る |
| `.page(name)` | ページを1枚足して `Page` を返す。名前がタブ名になる |
| `.save(path, force=False)` | ファイルへ書き出す。人の手直しがあれば書かずに止まる |
| `.to_xml()` | XML を文字列で返す。ファイルに書かずに中身を見たいときに使う |

### `save()` は勝手に上書きしない

`save()` は書き出す前に、その図に人の手が入っていないかを確かめる。
入っていれば例外を投げ、**1バイトも書き換えずに止まる**。
生成スクリプトは図を丸ごと作り直すため、人の手直しが跡形もなく消えるからである。

判定は SHA-256 のハッシュで行う。
書き出しに成功すると、図と同じ場所の `.drawio-baseline/<ファイル名>.json` に
そのときの内容のハッシュを控える。次に `save()` を呼んだとき、現在の内容と突き合わせる。

| 関数 | 用途 |
| --- | --- |
| `check_untouched(path)` | 状態と説明を返す。状態は `clean` / `touched` / `unknown` |
| `record_baseline(path, by=None)` | いまの内容を基準として台帳に控える。`save()` が自動で呼ぶ |

`unknown`（台帳が無い）でも止まる。判断できないものを黙って上書きしないためである。
既存の図が手つかずだと確信できるときだけ、`record_baseline()` を手で呼んで台帳を作る。
どうしても上書きが必要なときは `save(path, force=True)`。**手直しは戻らない。**

進め方の判断は SKILL.md 冒頭「この図は、人とAIが交互に直す」にある。

## Page — 図形を置く

| メソッド | 戻り値 | 用途 |
| --- | --- | --- |
| `title(text)` | ID | 図のタイトル |
| `section(text, x, y, w)` | ID | 1ページの中で段を分ける見出し。`group()` で囲んで分けない |
| `aws_frame(label, x, y, w, h)` | ID | システム全体を囲む枠 |
| `group(label, x, y, w, h)` | ID | ステップ群などをまとめる枠 |
| `actor(label, x, y)` | ID | 利用者 |
| `screen(label, x, y)` | ID | 画面 |
| `step(no, label, x, y)` | ID | ウィザードの1段階 |
| `lambda_box(label, x, y)` | ID | 処理。アイコンと箱の組を置き、箱のIDを返す |
| `tables(names, x, y, title, kind, cols)` | (枠ID, 幅, 高さ) | テーブル群。`kind` は `in`/`out`/`off` |
| `files(names, x, y, title, kind, cols)` | (枠ID, 幅, 高さ) | ファイル群 |
| `stores(names, x, y, title, kind, cols)` | (枠ID, 幅, 高さ) | DB以外の保存先（認証基盤・キュー・オブジェクトストレージ・外部システム） |
| `note(title, body, x, y)` | ID | 補足（黄） |
| `callout(title, body, x, y)` | ID | 吹き出し（橙）。誤解しやすい点の説明 |
| `small(text, x, y)` | ID | 図形のそばの小さな注釈 |
| `tbd(body, x, y)` | ID | 未確定事項（赤の破線）。AI注記が自動で付く |
| `scope_out(body, x, y)` | ID | この図では扱わない範囲 |
| `gen_box(body, x, y)` | ID | 世代・状態の説明ボックス |

`tables()` は幅と高さも返す。次の要素をその右に置くとき、`x + w + 40` のように使うと
座標を数えなくて済む。

## Page — 線を引く

| メソッド | 色・向き | 用途 |
| --- | --- | --- |
| `flow(src, dst, label)` | 灰 | 画面と処理のつながり |
| `self_loop(shape, label, side)` | 灰 | 画面の中だけで完結する操作。既定は右上 |
| `back(src, dst, label)` | 茶の点線 | 処理から呼び出し元の画面へ戻る |
| `read(frame, lmb, label)` | 青・下から上 | テーブルの読み取り |
| `write(lmb, frame, label)` | 緑・上から下 | テーブルへの書き込み |
| `delete(lmb, frame, label)` | 赤 | テーブルからの削除 |
| `cascade(src, dst, label)` | 赤の点線 | 外部キーによる連鎖削除 |
| `relate(src, dst, label)` | 紫 | 世代関係など補助的な関係 |
| `lead(src, dst)` | 赤の点線・矢印なし | 注記の引き出し線 |

`read` と `write` は接続位置が既定で入っているので、そのまま呼べば上下に線が出る。

### 語彙で表せないときの逃げ道

上の表に無い図形や線が要るときは、低水準の2つを直接呼ぶ。

**図形** — `node(value, style, x, y, w, h, kind="box", ident=None)`

`style` は drawio のスタイル文字列をそのまま渡す。
既定のスタイルは `S_SCREEN` `S_NOTE` などの定数にあるので、それを土台に足し引きすると早い。
`kind` は検査での扱いを決める種別（`screen` / `lambda` / `table` / `frame` / `note` / `text` /
`icon` / `box`）で、`validate_drawio.py` の重なり検査やはみ出し検査がこれを見る。
`ident` を渡すと ID を固定できる。既にある図と同じ ID にしたいときに使う。

**線** — `edge(source, target, label="", color=C_FLOW, dashed=False, arrow="block",
exit_xy=None, entry_xy=None, label_pos=None, points=None)`

線は完全な自由スタイルではなく、色・破線・矢先・接続位置・中継点の組み合わせで作る。

| 引数 | 意味 |
| --- | --- |
| `color` | 線とラベルの色。`C_FLOW` `C_READ` `C_WRITE` などの定数がある |
| `dashed` | 破線にする |
| `arrow` | 矢先の形。`block` / `open` / `none` |
| `exit_xy` / `entry_xy` | 接続位置を辺の割合 `("1", "0.5")` で指定する |
| `label_pos` | 線上のラベル位置。`-1`=始点、`0`=中点、`1`=終点 |
| `points` | 経路の中継点を `[(x, y), ...]` で渡し、通る場所を固定する |

`points` は、接続位置の指定だけでは直交ルータが経路を決めきれないときに使う。
線が図形を突き抜ける、ループが潰れて線に見えない、といった崩れはここで直す。

**まず語彙のメソッドで書けないかを考える。** 色や向きに意味を持たせてあるので、
低水準で書くとその意味が図から失われる。
既にある図を機械的に写し取るときのように、**元の見た目を保つ必要があるときだけ**使う。

### `back` はむやみに呼ばない

**戻る値がその先の流れを決めるときだけ呼ぶ。** 処理を呼べば何かが返るのは当たり前で、
「カラーマスタの一覧を返す → 表示色を返す」のように処理名で自明なものに線を引いても、
情報は増えず本数だけが増える。参照だけの機能では1本も残らないことがあり、それが正しい。

省く目的は、戻り線を**情報ではなく強調として使う**ことである。
値が次の処理や次の画面へ渡る箇所には実装の依存関係があり、
作る順序・担当の分担・インターフェースの決めごとが発生する。読み手はそこを見つけたい。
自明な戻り線まで引くと、その1本が同じ見た目の線に埋もれる。

呼ぶのは次のときである。判断の詳細は default_rules.md §3 にある。

```python
# 採番されたIDを次の処理が使う → 引く
p.back(l_accept, scr, "② 作業IDを返す")

# 値を画面遷移で次の画面へ渡す → 引く。ラベルに渡すキーを書く
p.back(l_create, scr, "② 採番されたアンケートIDを返す")

# 処理名で自明 → 引かない
# p.back(l_colors, scr, "表示色を返す")   ← 書かない
```

### 画面の中だけで完結する操作は自己ループで描く

`self_loop()` を使う。処理を呼ばずに画面内で終わる操作（保持している一覧の絞り込みなど）に使う。
処理の箱が無いこと自体が「Backend を作らなくてよい」という情報になる。

```python
p.self_loop(scr, "① 条件を変える → 画面内で絞る")
p.small("対象は4条件。保持している行を絞るため<b>処理を呼ばない</b>。", 900, 1140, 560, 50)
```

**既定は画面の右上である。** 3段構成では画面の下を処理へ降りる線が必ず通り、
左右は前後の画面への遷移線でふさがっているため、構造的に空いているのは上だけである
（既定ルール §2 を参照）。段の見出しと画面の間は 60px 以上あける。

下に置きたいときだけ `side="bottom"` を渡す。
その画面が処理を呼んでいなければ下も空いているので、そのときは選んでよい。

```python
p.self_loop(scr, "並び順を変える → 画面内で並べ替える", side="bottom")
```

`gap`（辺からの距離。既定44px）と `span`（出口・入口の位置。既定 `(0.65, 0.9)`）でも調整できる。

**`flow()` の始点と終点に同じ画面を渡してはいけない。** `ValueError` になる。
接続位置の指定だけでは drawio の直交ルータが自己ループの経路を決めきれず、
2点を近づけるとループが潰れて線に見えず、離すと戻り脚が画面の箱を突き抜けるためである。
`self_loop()` は中継点を置いて経路を固定するので、形が必ず決まる。

## 座標の目安

```
Y_SCREEN = 140   上段：画面
Y_LAMBDA = 330   中段：処理
Y_TABLE  = 420   下段：テーブル
Y_NOTE   = 760   補足
```

横方向は、処理を呼び出し元の画面の真下に置けるよう、画面の x に合わせる。

テーブル群を処理の真下に置くときは、**中心をそろえる**。
`lambda_box(x)` は x+42 の位置に幅220の箱を置き、`tables()` の枠は幅256になるため、
枠の x は「箱の x から 13 引いた値」にすると中心が合う（箱が 832 なら枠は 819）。
列数を増やすと枠の幅が変わるので、そのつど計算する。

## つまずきやすい点

### 線が図形を突き抜ける

`exit_xy` / `entry_xy` で接続位置を指定して経路を誘導する。

```python
p.flow(scr, lmb, "保存", exit_xy=("0", "0.5"), entry_xy=("0", "0.5"))
```

左辺から出して左辺へ入れると、図形の左側を回る経路になる。
真下へ降ろすと途中の枠を突き抜けるときに使う。

### ラベルが遠くの図形に重なる

長い線では中点にラベルが置かれる。`label_pos` で終点寄りに寄せる。

```python
p.flow(step, lmb, "保存して次へ", label_pos=0.85)
```

`-1` が始点、`0` が中点、`1` が終点。0.8〜0.9 で線の行き先の近くに来る。

### テーブルが多くて縦に伸びる

`cols` で列数を増やす。8件を2列にすれば高さが半分になる。

```python
p.tables(names, x, y, "書き込み先", kind="out", cols=2)
```

### 同じテーブルが複数の処理に出てくる

重複して描いてよい。処理ごとに流れを追えることを優先する。
凡例ページにその旨を書いてあるので、読み手は混乱しない。

### テーブル群の枠を縦に積むと検査に引っかかる

`validate_drawio.py` は「枠の中に入っている図形が枠の外へ出ていないか」を見る。
テーブル群の枠を別のテーブル群の真下に置くと、下の枠の中身が上の枠からはみ出していると
判定される。**テーブル群は横に並べる。** 連鎖削除のように上下関係を示したいときも、
横に並べて線で結ぶ。

### 箱の高さは渡さない

`note()` `callout()` `tbd()` `scope_out()` `small()` `text()` `gen_box()` は、
高さ `h` を省略すると本文と幅から必要な高さを見積もる（`estimate_height()`）。
高さを自分で決めると、本文を1行足すたびに数値を当て直すことになり、
その手直しが作図の時間の大半を占める。

見積もりは drawio の折り返しを Python 側で真似ているだけなので、描画とは数 px ずれる。
文字が切れるより余白が余るほうが害が小さいため、余る側へ寄せてある。

高さを渡した場合はその値を尊重する。あふれているかどうかは `validate_drawio.py` が
検査6「文字が箱に入りきらない」で指摘する。

### 注記が図形に重なる

`note()` `callout()` `tbd()` `scope_out()` は、画面や処理と同じく重なり検査の対象になる
（`small()` だけはテキスト扱いで対象外）。次の2つを守ると、座標の調整をやり直さずに済む。

- 注記は `Y_NOTE`（760）以降に置く。図の本体と縦方向で分ける
- 注記どうしは横に 340px 以上あける。`note()` の見出しが幅320px 固定のため、
  それより詰めると隣の注記の見出しと重なる

### 処理の箱を高くしたら、テーブルの段も下げる

`lambda_box(h=76)` のように2行のラベルにすると、箱の下端が `Y_TABLE`（420）に近づき、
`write()` のラベルを置く余白がなくなる。処理を高くしたページでは、
`Y_TABLE` を 480〜540 あたりまで下げる。段の位置はページごとに変えてよい。

### 1つの処理から複数の画面へ分岐する

「処理は呼び出し元の画面の真下」という原則は、分岐があると成り立たない。
行き先の画面を縦に積むと、その画面から呼ばれる処理を置く場所がなくなるためである。
このときは段の Y 座標をページ単位でずらす。原則より読みやすさを優先してよい。

## 凡例ページ

```python
from drawio_builder import legend_page

legend_page(
    d,
    schemas=[("アンケート実施スキーマ", "survey"), ("共通データ基盤スキーマ", "common")],
    tables=[("アンケート配信設定", "survey.survey_plan_master"), ...],
    steps=[("ステップ1", "BYR区分"), ...],      # 省略可
    scope="・〜を対象とする。<br>・現行の実装（As-Is）をそのまま図にしている。",  # 省略可
)
```

記号・線の色・読みかた・T.B.D の書式は共通なので、この関数が用意する。
渡すのはプロジェクト固有の対応表だけでよい。

## 生成したあと

```bash
python scripts/validate_drawio.py 出力.drawio      # 重なり・参照切れ・はみ出し
python scripts/preview_drawio.py 出力.drawio --serve # ブラウザで目視
```

検査を通しても、線の経路の読みにくさは分からない。出す前に一度は目で見る。

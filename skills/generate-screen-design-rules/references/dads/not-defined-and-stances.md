# DADSで値が定められていない項目と、DADSの方針

規約を作るときに、次の2点を先に確認する。

1. DADSに**値が書かれていない項目**は、プロジェクトの規約として値を決める。
2. DADSの**方針**が、部品ライブラリの標準の動きと食い違いやすい項目は、採用の可否を決める。

確認日: 2026-10-04（ローカルの原文の取得日は `VERSION.txt` を参照）。DADSが更新されたら確かめ直す。

## 1. 値が定められていない項目

| 項目 | DADSの記載 | 規約での扱い |
| --- | --- | --- |
| 余白の値の一覧 | 基準は8px。適用例は8・24・64px。確定した一覧はない | プロジェクトで一覧を決める |
| 角丸の、部品ごとの値 | スタイル（0・8・16・32・フル）はあるが、部品ごとの値はない | 部品ごとに、スタイルを割り当てる |
| 影の、用途ごとのレベル | レベル1〜8の値はあるが、どの部品がどのレベルかはない | 部品ごとにレベルを決める |
| オーバーレイシェード（ダイアログの背景）の色と透過度 | 記載なし | 決める |
| フォーカスの線の太さ | 色（Yellow-300と黒の2重）はあるが、太さはない | 決める |
| 主要な色（Primary、Secondary、Tertiary）の段階 | コントラスト比の要件だけで、どの段階かはない | 色相を決めて、要件を満たす段階を選ぶ（`scripts/contrast.py`） |
| 情報（Info）の色のトークン | Success、Error、Warningはあるが、Infoはない | 「情報提示1はプライマリーの色相」の記載から決める |
| テキストと背景の、使う組み合わせ | 要件だけ | 使う組み合わせを、`scripts/contrast.py` で確かめる |
| 表の行の高さ | Default・Denseの区別はあるが、値はない | 決める |
| 入力欄のうち、select・textarea・checkbox・radio・date-pickerの寸法 | input-textの高さだけある | 決める |
| ボタンの内側の余白（padding） | 最小の幅と高さだけある | 決める |
| モーダルの幅 | 記載なし | 決める |
| 見出しのレベル（h1〜h6）とテキストスタイルの対応 | 「スタイルガイドで定義する」とだけある | 対応を決める |
| コンテンツの最大幅、左メニューの幅 | 記載なし（左メニューの幅はCarbonで補う） | 決める |
| 想定する画面の幅（PC） | ブレークポイントの設定例（768px）だけ | 想定の画面の幅を決める |
| タブの数の目安 | DADSにはなし（Carbonで補う） | Carbonの値を採用するか決める |
| モーダルとサイドパネルの使い分けの基準 | DADSにも、Carbonのモーダルの資料にもない | 決める |

**手順**: 値を決めたら、規約の本文に値を書き、出典の資料（`sources.md`）の「プロジェクト独自ルール」の表に、**決めた理由**を書く。

## 2. DADSの方針と、部品ライブラリの標準が食い違いやすい項目

| 項目 | DADSの方針 | 確認すること |
| --- | --- | --- |
| ダイアログにフォームを入れる | 入れない（取り消せない操作の確認と、短いメッセージに使う） | 確認のための入力欄を1つだけ置くなど、例外を認めるか |
| ボタンの無効化（disabled） | 原則として使わない。使う場合は、理由と有効になる条件を近くに表示する | 実行できない状態のボタンを、無効にするか、押せるようにしてエラーを出すか |
| 入力欄の読み取り専用（readonly） | 避ける。許容する場合は、点線の枠と理由を表示する | 編集できない値を、入力欄で見せるか、別の部品で見せるか |
| プレースホルダー | ラベルの代わりに使わない | 部品ライブラリの標準のラベルの動きでよいか |
| ラベルの位置 | 入力欄の上に置く。入力欄の中には置かない | 入力欄の枠に重なる形（部品ライブラリの標準）を認めるか |
| 入力欄の最大文字数（maxlength）、貼り付けの禁止 | 使わない | 使うか |
| エラーを出すタイミング | 送信のあと。入力の途中やフォーカスが外れたときは避ける | 部品ライブラリの標準の検証のタイミングを変えるか |
| エラーの表示 | 入力欄の下に左寄せ。先頭に「＊」。色だけに頼らない | 文言の書き方を決めるか |
| 日付の入力 | 年・月・日を別の入力欄にする。`select`や`input type=date`は避ける | 標準の日付の部品を使うか |
| 選択肢が少ないselect | 5つ以下ならラジオボタン | 使い分けの基準を決めるか |
| 表のセルの結合 | データテーブルでは原則として結合しない | 結合を認めるか |
| 行全体をリンクにする | できない（リンクはセル単位） | 行を押したときの動きを決めるか |
| 色だけでの区別 | 禁止 | 選択中、エラーなどの表し方（アイコン、太字、枠の太さ）を決めるか |

**手順**: 採用しない方針や、例外にしたものは、規約の本文に理由とともに書き、`sources.md` の「プロジェクト独自ルール」の表にも書く。

# プロジェクト固有情報の反映

次をユーザーの指示と既存資料から確認し、決定済みの内容を正本へ反映する。
確認済みの項目は繰り返し質問しない。

| 確認項目 | 反映先 |
| --- | --- |
| アプリの目的、利用者、対象範囲 | `README.md`、必要な要件資料。 |
| サービスの責務、Python採用の有無、サービス間の境界 | `docs/20_rules/アーキテクチャ.md`、各サービスの設計。 |
| DBの所有者、DDLやマイグレーションの責任、参照先 | 全体とサービスのアーキテクチャ、必要な運用手順。 |
| 認証・認可、環境、デプロイと外部操作の権限 | アーキテクチャと実際の運用手順。 |
| AWS識別名、環境名、リージョン、サービス略称 | AWSリソース命名規則。秘密情報を記載しない。 |
| 業務用語と略語 | `docs/30_glossary/用語集.md`。 |
| AIと人のレビュー・Git運用、課題管理先 | リポジトリ規約と必要なAI指示。 |
| 使用ツールと必要なスキル | AI向け指示、スキル配置と同期方針。 |
| 実行可能なセットアップ、ローカル確認、テスト | 実装・環境を確認後に対象別の手順書。 |

人向け規約を正本とし、AI向け指示には作業に必要な要約とリンクを記載する。
共通部品名やコマンドは、実在を確認するか、設計上の要求であることを明示する。
未決定事項は合意した課題管理先で管理し、ユーザーから権限を与えられていない外部サービスへの登録はしない。
未決定の節は対象プロジェクトの文書規約に従い扱い、管理先がなければ完了報告に残す。

スキルの採用時は対象作業、出典、ライセンス、依存と付属ファイルを確認する。
複数ツールでスキルを複製する場合は正本、同期方法、双方の検証方法を定める。

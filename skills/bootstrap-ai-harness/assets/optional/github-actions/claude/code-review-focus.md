# PRレビューの重点

このファイルは、GitHub Actionsの自動レビュー（`.github/workflows/claude-code-review.yml`）だけが読む。
レビューのコメントは、日本語で書く。

## 確認すること

1. **規約への準拠**
   `AGENTS.md`、`docs/20_rules/`、`nuxt/docs/20_rules/`、`backend/*/docs/20_rules/` の規則に、明確に違反している箇所を指摘する。
   違反した規則を、引用して示す。
2. **水平展開の漏れ**
   変更が、複数のサービスやファイルに及ぶ性質のものであるとき、リポジトリ内を検索して、同じ修正が必要な箇所の直し漏れを指摘する。
   直し漏れは、この変更が原因で生じる問題であり、既存の問題ではない。指摘の対象とする。
   確かめるために、差分の外のファイルを、調べること。
   コメントは、差分の該当する行に付け、漏れている箇所を、ファイルのパスで本文に示す。
3. **文書間の整合**
   変更した文書と、その文書が参照する文書、その文書を参照する文書との間の、記述の食い違いを指摘する。
   食い違いは、この変更が原因で生じる問題として、指摘の対象とする。
   確かめるために、差分の外の文書を、調べること。
4. **リンクの有効性**
   プロジェクト内へのリンクについて、リンク先のファイルと見出しが存在することを、確認する。
   外部のURLは、確認しない。
5. **純粋な不具合**
   構文エラーや、明らかな誤動作を指摘する。

## 確認しないこと

- 要件や仕様が正しいかどうか。要件や設計書が、リポジトリの外にあり、リポジトリから見えない場合は、判断できないため、対象外とする。
- 好みや、書き方の提案。

## 指摘のしかた

- 根拠（規則の該当箇所、または、漏れている箇所のパス）を示せるものだけを指摘する。確信のないものは、指摘しない。
- 問題がなかった場合も、確認した観点を、日本語で報告する。

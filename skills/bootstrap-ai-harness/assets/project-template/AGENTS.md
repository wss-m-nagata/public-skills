# AI向け作業指示

## 対象と役割

このリポジトリは{{プロジェクト名}}のWebアプリを管理する。
AIが変更し、人がレビュー、必要な調整、コミットを行う。
コミット、プッシュ、プルリクエストのマージは人が行う。
変更前に方針と理由を簡潔に伝え、初めて読む人にも分かる内容にする。

## 参照先

- 作業と文書の規則は[リポジトリ規約](docs/20_rules/リポジトリ規約.md)に従う。
- 構成と資料配置は[アーキテクチャ](docs/20_rules/アーキテクチャ.md)に従う。
- Pythonは[Pythonコーディング規約](docs/20_rules/Pythonコーディング規約.md)、Python APIは[API実装方針](docs/20_rules/API実装方針.md)に従う。
- TypeScriptとVueは[Node.jsコーディング規約](docs/20_rules/Node.jsコーディング規約.md)、画面は[フロントエンド実装方針](nuxt/docs/20_rules/フロントエンド実装方針.md)に従う。
- テストは[テスト規約](docs/20_rules/テスト規約.md)と[E2Eテスト作成規約](docs/20_rules/E2Eテスト作成規約.md)に従う。

## 設計の作業に使うスキル

- 画面設計規約の作成・更新には `generate-screen-design-rules` を使う。
- 画面・バックエンド・データの関係を示す処理フロー図には `process-flow-diagram` を使う。
- 画面一覧、画面遷移、画面設計書や画面単体テスト仕様書のExcelには `nablarch-frontend-design-excel` を使う。
- バックエンドのAPI・テーブルなどの設計書や単体テスト仕様書のExcelには `nablarch-basic-design-excel` を使う。
- 対象スキルと付属資料の所在、実行環境を確認してから作業し、プロジェクトの規約と決定事項を優先する。

日本語で応答し、UTF-8 BOMなしとLFを使用する。
コード変更時は対象の仕様と既存実装を確認し、適切なテストを実施し、未実施の検証を報告する。

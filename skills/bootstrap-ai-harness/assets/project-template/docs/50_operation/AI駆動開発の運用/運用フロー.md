# 運用フロー

このプロジェクトのAI駆動開発の、作業の進め方を示す。  
目的、スタンス、役割、スキル、ハーネスは、[README.md](README.md)にある。  
図は、[運用フロー.drawio](運用フロー.drawio)にある（3ページ：全体フロー、設計工程、開発・テスト工程）。

## 範囲

- 設計の依頼から、開発環境での試験と、設計書の正式版への反映までを、範囲とする。  
- 課題管理（Backlogなど）への起票と、課題からの着手は、この運用に含まない。  

## 図の読み方

担当は4つに分かれる（AIが行う／人が判断する／外部が判断する／作業の記録）。  
AIの箱には、「読むもの」「使用スキル」「ルール（ハーネス）」を書く。  
人の箱には、「見るもの」「判断すること」を書く。  

## 全体フロー（図1ページ目）

| No | 担当 | 作業 | 読む・見るもの | つくるもの・判断 |
|---|---|---|---|---|
| 0 | 人 | 要件定義書・画面詳細設計書を作る | — | 要件定義書・画面詳細設計書（AIの入力） |
| 1 | AI | 設計書の案をつくる。設計チケットを作り、経緯・進捗を記録する | 要件定義書・画面詳細設計書・WBS・スキル | 設計書（案） |
| 2 | 人 | 案を確認して、外部に依頼する | 設計書（案） | OK→レビュー用に置く。直す→AIに指示 |
| 3 | 外部 | 外部がレビューする | 設計書（案） | 合意するか |
| 4 | 人 | 正式版に反映する（AI支援：反映スクリプト提供。実行は人）。設計チケットを閉じる | — | 設計書（正式版） |
| 5 | AI | プログラムとテスト仕様書をつくり、試験する。実装チケットを作り、経緯・進捗を記録する | 正式版の設計書・ハーネス | プログラム・テスト仕様書・試験結果 |
| 6 | 人 | 結果を確認し、開発環境に配備する（GitHub にプッシュして行う） | 試験結果 | OK→配備。直す→AIに指示 |
| 7 | AI | 開発環境で試験し、設計書を実装に合わせて直す。修正の経緯を記録する | 配備したプログラム・設計書 | 試験結果・設計書（修正案） |
| 8 | 外部 | 外部がレビューする | 設計書（修正案） | 合意するか |
| 9 | 人 | 正式版に反映し、取り込む。完了を記録する | 試験結果 | OK→取り込み、チケットを閉じる |

- 設計書を直したときも、人が確認してレビュー用に置き、外部レビューを経て正式版に反映する（設計工程と同じ手順）。  
- プッシュする前には、AIが全テスト・AIレビュー・規約チェックを流し、人が結果を確認する（開発・テスト工程）。  

## 設計工程（図2ページ目）

AIが資料を読んで設計書の案をつくり、人が判断する。  
外部のレビュー担当者と合意してから、正式版に反映する。  

| No | 担当 | 作業 | 読む・見るもの | つくるもの・判断 | 使用スキル | ルール（ハーネス） |
|---|---|---|---|---|---|---|
| 1 | 人 | 設計する機能を決めて、資料を渡す | — | 要件定義書・画面詳細設計書・WBS・連携仕様 | — | — |
| 2 | AI | チケットを作る（作成前に人が確認） | 依頼の内容 | 設計用チケット | チケットの作成 | 共通の指示書・Git運用規約 |
| 3 | AI | 設計書の案をつくる | 要件定義書・画面詳細設計書など | 設計書の案（処理フロー図・API仕様書・ER図・テーブル定義書） | 設計書の修正手順（全体）、処理フロー図の作成、API仕様書・テーブル定義書の作成、ER図の作成 | 共通の指示書・開発規約（DB） |
| 4 | AI | 変更箇所一覧と確認資料をつくる | 設計書の案 | 変更箇所一覧（何が変わるか）・確認資料（判断してほしい点） | 変更箇所一覧・確認資料の作成 | 共通の指示書 |
| 5 | 人 | 案をレビューして、判断する | 設計書の案・一覧 | OK→次へ。直す→AIに指示 | — | — |
| 6 | 人 | レビュー用の場所に置き、外部に依頼する（AIは直接置けないため、人が実行） | — | — | 設計書の修正手順（配置用スクリプト） | — |
| 7 | 外部 | 外部がレビューする | 設計書・変更箇所一覧 | 合意するか | — | — |
| 8 | 人 | 正式版に反映する（AI支援：反映スクリプト提供。実行は人） | — | 設計書（正式版） | 設計書の修正手順（反映用スクリプト） | — |

人が結果を確認してから、取り込む。  

| No | 担当 | 作業 | 読む・見るもの | つくるもの・判断 | 使用スキル | ルール（ハーネス） |
|---|---|---|---|---|---|---|
| 1 | AI | チケットを作り、実装の方針を整理する（作成前に人が確認） | 正式版の設計書 | 開発用チケット・実装方針案 | チケットの作成 | 共通の指示書・サービス別の指示書・開発規約・Git運用規約 |
| 2 | 人 | 方針を決める | 実装方針案 | 方針・未決事項 | — | — |

| 8 | AI | 設計書を直す | 実装で決めたこと・設計書 | 設計書の修正案 | 設計書の修正手順 | 共通の指示書・Git運用規約 |

## AIが守る決まり

- AIは、人の確認なしに先へ進まない。  
- チケットは、作成前に、人が確認する。  
- {{設計書の正式版の置き場所}}の設計書は、AIが直接は書き換えない。  
  AIは、配置用・反映用のスクリプトを作る。  
  実行するのは、人である。  
- 開発環境への配備は、人が、GitHub にプッシュして行う。  
- 変更箇所一覧と確認資料を作る前に、レビューを依頼しない。  
- 単体テスト仕様書は、実装が終わってから作る。  
- テストが失敗したときは、テストや期待値を直さず、原因を報告して、人の判断を待つ。  
- プッシュ前に、AIが全テスト・AIレビュー・規約チェックを流し、人が結果を確認してから、プッシュする。  
- チケットを閉じるのは、人である。  

## 利用ツール

### AIの実行環境

| 名前 | 役割 |
|---|---|
| Claude Code | AIが作業する場所。コマンドラインから使う、AIの開発ツール |

### MCP

接続先や鍵は、プロジェクトで用意する。  

| 名前 | 役割 | 使う場面 |
|---|---|---|
| context7 | ライブラリやツールの、最新の資料を取得する | ライブラリの調べもの |
| playwright | ブラウザを操作する | ブラウザでの確認 |
| drawio | 図（drawio）を作る・開く | 処理フロー図、ER図の作成 |
| dbhub | データベースの内容を確認する（参照のみ）。データベースを使う場合に用意する | 実装・試験での、データの確認 |
| desktop-commander | ファイルの読み書きと、コマンドの実行を、文字化けなく行う | 日本語のファイルの読み書き |

### スキルが使う道具

| 道具 | 役割 | 主に使うスキル |
|---|---|---|
| gh（GitHub CLI） | GitHub の Issue の参照・更新、PR の操作を行う | チケットの作成、プッシュ前の確認 |
| git | 変更履歴を管理する（ブランチの作成など） | チケットの作成、プッシュ前の確認 |
| Python | スキルのスクリプトを実行する | 設計書・図・チケットの作成の、各スキル |
| Python のライブラリ（openpyxl、Pillow、PyYAML） | Excel の作成・更新、画像の加工、設定ファイルの読み込み | API仕様書・テーブル定義書・単体テスト仕様書の作成、チケットの作成 |
| uv | Python の実行環境を用意して、テストを動かす | プッシュ前の確認 |
| Node.js、npx、pnpm | Node 系の道具を実行する（MCP の起動、手元の全テスト） | 自動試験の作成、プッシュ前の確認 |
| Playwright | ブラウザ・API の自動試験を行う | 自動試験の作成 |
| Excel 本体（Windows） | Excel の見た目を確認する（画像に書き出す） | API仕様書・テーブル定義書の作成 |
| draw.io | 図（処理フロー図・ER図）を表示・編集する | 処理フロー図の作成、ER図の作成 |

### ハーネスを動かす道具

| 道具 | 役割 | 使う場面（図の箱） |
|---|---|---|
| フック（Claude Code の機能） | AIの操作のあとに、決まった処理を自動で動かす（コード整形）。保存時の整形のフックを設定した場合に使う | プログラムをつくる |
| Prettier、Black、ESLint | TypeScript・Vue・JSON、Python のコードの書き方を、自動で整える。ESLint は、コードの検査を行う（フックから動かす） | プログラムをつくる |
| pytest | Python の単体テストを行う | テスト仕様書をつくり、試験する |
| Playwright | API・ブラウザの試験を行う | 開発環境で試験する |
| 手元の全テストのスクリプト | 全テストを手元で流して、結果の一覧を出す | プッシュ前の確認 |
| Claude Code Action | GitHub 上で、PR のAIレビューと、Issue の自動ラベル付けを行う。GitHub Actions を設定した場合に使う | 図にはなし。GitHub 上での、PR の確認と、Issue の分類 |

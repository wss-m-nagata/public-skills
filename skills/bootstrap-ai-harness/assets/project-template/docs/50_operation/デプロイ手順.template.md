管理者が環境を新しく構築するときと、構築済みの環境を更新するときの手順を示す。

## 新しい環境の構築

1. 組織の手順で AWS にサインインする。
   `aws sts get-caller-identity` で対象アカウントを確認する。
2. デプロイ先のアカウントとリージョンの組ごとに、CloudFormation の `CDKToolkit` スタックを確認する。
   未実施の組で `npx cdk bootstrap aws://<アカウントID>/<リージョン>` を実行し、スタックの作成結果を確認する。
   CloudFront 用 WAF を配置する場合は `us-east-1` も対象に含める。
3. GitHub Actions を使う場合は、AWS アカウントの GitHub 用 OIDC プロバイダーを確認する。
   未作成の場合は IAM の ID プロバイダーで `https://token.actions.githubusercontent.com` と対象者 `sts.amazonaws.com` を登録する。
   管理基盤の CDK アプリで `npx cdk diff <スタック名> -c env=<環境名>` を実行し、対象を確認してから `npx cdk deploy <スタック名> -c env=<環境名>` でデプロイする。
4. [CDK 作成方針](../20_rules/CDK作成方針.md#初回デプロイの依存関係)のうち、採用した構成の順序でデプロイする。
   各スタックの作成結果を確認してから、そのスタックを利用する側を進める。
   この項目は、実際の実行場所、コマンドまたはワークフロー、対象スタックと成功条件を記載して完成させる。
5. デプロイ先のブラウザーで画面を開き、ログインが必要な場合はログインする。
   対象の業務画面と API が応答することを確認する。

## 構築済みの環境の更新

対象環境ごとに、画面・API・共通インフラの変更が自動で反映される条件と、手動で実行する作業を記載する。
ワークフローを使う場合は、変更対象、ブランチ、承認条件、対象スタックの選択と成功確認を記載する。

### アカウントを追加・削除するとき

Cognito と認証アプリによる二要素認証を採用する場合の流れを示す。

1. 管理者が、対象環境の利用者一覧または管理画面でアカウントを追加・削除する。
   一覧をデプロイで反映する構成では、認証スタックの差分を確認してから反映する。
2. アカウントを追加した場合は、招待メールを受け取った利用者が、メールに記載された URL を開く。
3. 利用者が仮パスワードでログインし、新しいパスワードを設定する。
4. 利用者が認証アプリで画面の QR コードを読み取り、表示されたコードを入力する。
5. 利用者が再ログインし、認証アプリのコードで業務画面を開けることを確認する。

### 認証設定やデプロイ権限を変更するとき

1. 設定を変更し、対象のスタックと差分を確認する。
2. 対象環境の手順で変更を反映する。
3. 認証設定の変更ではログインし、デプロイ権限の変更では対象のデプロイ操作を行って反映を確認する。

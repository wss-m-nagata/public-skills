# CDKコーディング規約

本ドキュメントは、このプロジェクトのCDK（TypeScript）のコードを書くときの決まりを定める。

## 環境の値の置き場所

環境ごとに変わる値は、`cdk.json`の`context`の`environments.<環境名>`に書く。  
コードには、環境ごとの値を直接書かない。  
環境ごとの設定の型は、CDKアプリの`lib/config.ts`に定義する。

**理由**: 環境を増やすときに、コードを変えず、`cdk.json`に環境を足すだけで済むようにするためである。

## 環境名の扱い

- 環境名は、`-c env=<環境名>`で指定する（例: `-c env=dev`）。
- 環境名が未指定のとき、または`cdk.json`に定義がないときは、エラーで止める。
- スタック名とリソース名の環境名には、指定された環境名を使う。  
  名前の形式は、[AWSリソース命名規則.md](AWSリソース命名規則.md)に従う。

**理由**: 環境名の指定を忘れたまま、意図しない環境にデプロイするのを防ぐためである。

## バージョンの固定

- `aws-cdk-lib`と`aws-cdk`は、範囲指定（`^`や`~`）を使わず、バージョンを1つに固定する。
- すべてのCDKアプリで、`aws-cdk-lib`と`aws-cdk`を同じバージョンにそろえる。
- バージョンを上げるときは、すべてのCDKアプリを同時に上げる。

**理由**: CDKアプリが複数あるため、バージョンがずれると、同じ書き方でも、生成されるテンプレートが変わるおそれがあるためである。

## タグ

すべてのスタックに、次のタグを付ける。

| タグ | 値 |
| --- | --- |
| `project` | プロジェクトのAWS識別名 |
| `environment` | 対象の環境名 |
| `app` | 管理基盤Appは`foundation`、共通インフラAppは`shared`、サービスAppはサービスの略称 |

- タグのキーは、すべて小文字にする。
- タグは、スタックごとではなく、CDKアプリ全体に付ける（`Tags.of(app)`）。

**理由**: 同じAWSアカウントに、ほかのシステムが同居しているため、このシステムの費用を、環境とCDKアプリごとに分けて見られるようにするためである。  
タグのキーは、大文字と小文字を区別するため、`App`と`app`は別のタグになり、費用の集計から漏れる。  
キーをすべて小文字にして、書き方に迷わないようにする。  
CDKアプリ全体に付けると、付け忘れを、構造で防げる。

## 削除保護

- 環境ごとに、`deletionProtection`（真偽値）を、`cdk.json`の`environments`に持つ。
- 本番環境は`true`とする。開発・検証環境は作り直しの可否に応じて設定する。
- `true`のときは、スタックの削除保護（`terminationProtection`）を有効にする。

**理由**: 本番環境で、スタックの誤削除によって、ユーザーや秘密情報が消えるのを防ぐためである。  
開発・検証環境では、作り直しが多く、削除保護があると、作業の妨げになる。

## リソースの削除の扱い（`removalPolicy`と`cdk destroy`）

- データを持つリソース（Cognitoのユーザープール、Secrets Manager、画面のS3、ロググループ）の`removalPolicy`は、`deletionProtection`が`true`のとき`RETAIN`、`false`のとき`DESTROY`にする。
- データを持たないリソース（Lambda、APIなど）は、CloudFormationの既定のままにする。
- `cdk destroy`は使わない。  
  スタックの削除は、管理者が、削除するスタック名を確認して、`aws cloudformation delete-stack`で行う。  
  削除保護が有効なスタックは、先に解除する。

**理由**: 本番環境で、スタックを削除しても、データを持つリソースを残すためである。  
作り直す環境で`RETAIN`にすると、同じ名前のリソースが残り、作り直しに失敗する。  
`cdk destroy`は、環境の指定を誤ると、意図しない環境のスタックを削除するおそれがある。  
スタック名を、削除のたびに明示することで、誤りに気づける。

## 秘密情報の扱い

パスワード、秘密鍵、アクセストークンなどの値は、CDKソースコード、環境設定、CloudFormationの出力やログに記載しない。
設定には秘密情報の名前やARNなどの参照先を記載する。
秘密情報はAWS Secrets Managerなどで管理し、必要な処理が取得する。

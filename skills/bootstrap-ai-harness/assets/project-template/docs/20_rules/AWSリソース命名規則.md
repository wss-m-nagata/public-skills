# AWSリソース命名規則

## 基本ルール

リソースの識別名、環境名、サービスの略称を明確にし、同じ環境内で重複しない名前にする。
リソースごとの使用可能文字と長さの制限を確認する。
基本は英小文字・数字・ハイフンとし、要素間の区切りにハイフンを使う。
SSMパラメータとシークレットは階層をスラッシュで区切る。
要素の中ではハイフンを使わず、単語をつなげる。
大小文字の扱いや記号の制約が異なるリソースでも、共通の形式で名前を読み取れるようにするためである。

| 要素 | 決定内容 |
| --- | --- |

リージョンを名前に含める場合は、リージョン名からハイフンを除く。
例えば`ap-northeast-1`は`apnortheast1`とする。
機能名は機能を表す英小文字と数字で付ける。

## サービスの略称の一覧

{{サービスごとの略称と対応}}

サービスの略称は英小文字と数字で8文字以内、機能名は英小文字と数字で20文字以内を基本とする。
長さを制限するのは、接頭辞と環境名を含むIAMロール名が上限を超えにくくするためである。
識別名や環境名の長さによっても結果は変わるため、実際の名前を個別に検査する。

## リソースごとの形式

| リソース | 形式 |
| --- | --- |
| 共有インフラのスタック | `{識別名}-webapp-{環境}` |
| GitHub Actions用IAMロールのスタック | `{識別名}-githubactions-{環境}` |
| サービスのスタック | `{識別名}-{サービス略称}-{環境}` |
| Lambda | `{識別名}-{サービス略称}{機能名}-{環境}` |
| Lambda用IAMロール | `{識別名}-rolelambda{サービス略称}{機能名}-{環境}` |
| GitHub Actions用IAMロール | `{識別名}-rolegithubactions{デプロイ対象}-{環境}` |
| API Gateway | `{識別名}-apigw{サービス略称}-{環境}` |
| API Gatewayのステージ | `{環境}` |
| CloudFront | `{識別名}-cf-{環境}` |
| CloudFront Functions | `{識別名}-cf{機能名}-{環境}` |
| Cognitoのユーザープール | `{識別名}-userpool-{環境}` |
| Cognitoのアプリクライアント | `{識別名}-webapp-{環境}` |
| Cognitoのドメイン（先頭部分） | `{識別名}-webapp-{環境}` |
| 画面配信用S3 | `{識別名}-frontend-{リージョン}-{環境}` |
| パラメータストア | `/{識別名}/{環境}/{サービス略称}/{値の名前}` |
| Secrets Manager | `{識別名}/{環境}/{サービス略称}/{値の名前}` |
| CloudWatch Logsのロググループ | `/aws/lambda/{Lambda名}` |

採用するリソースの命名制約と長さの上限を確認し、衝突しないようにする。
サービス略称はサービスごとに定め、他のサービスと重複させない。
GitHub Actions用IAMロールのデプロイ対象は、共有インフラまたは対象サービスを識別できる値とする。
共有インフラの値をSSMパラメータストアに登録する場合は、サービス略称の位置に`webapp`を使う。
Cognitoなどの認証用リソースは、対象プロジェクトで採用した場合に命名形式を適用する。
秘密情報の値はこの文書に記載しない。

例えば、識別名`library`、環境`dev`、サービス略称`books`、機能名`search`の場合、Lambdaは`library-bookssearch-dev`、そのIAMロールは`library-rolelambdabookssearch-dev`とする。
APIのURLを格納するSSMパラメータは`/library/dev/books/apiurl`とする。

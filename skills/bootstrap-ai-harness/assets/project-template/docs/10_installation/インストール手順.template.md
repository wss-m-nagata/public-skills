# インストール手順

Nuxt・Vue・Vuetifyの画面、Pythonのバックエンド、AWS CDK、Playwrightを開発するための準備を行う。
コマンドはWindowsのPowerShellを例とし、作業場所はWebアプリのリポジトリのルートとする。

## 前提条件

- リポジトリを取得し、PowerShellでそのルートを開く。
- ソフトウェアのインストールと必要なネットワークへの接続が許可されていることを確認する。
- 各ツールのバージョンは、プロジェクトの規約と設定ファイルに合わせる。Node.jsは[Node.jsコーディング規約](../20_rules/Node.jsコーディング規約.md)に従う。
- 依存関係の導入は、対象ディレクトリの設定ファイルが用意されてから行う。ファイルがなければ推測して作らず、アプリの実装時に準備する。

## 1. 開発ツールを準備する

| ツール | 用途 | インストールと確認 |
| --- | --- | --- |
| Git | ソースと資料の取得・変更管理 | [Git公式](https://git-scm.com/install/)から導入し、`git --version`で確認する。 |
| Node.js・npm | Nuxt、CDK、Playwrightの実行 | [Node.js公式](https://nodejs.org/en/download)から規約に合うNode.jsを導入し、`node --version`と`npm --version`で確認する。npmはNode.jsに付属する。 |
| pnpm | `nuxt/`の依存関係管理 | プロジェクト指定の版を[公式手順](https://pnpm.io/installation)で導入し、`pnpm --version`で確認する。 |
| Python・uv | Pythonサービスの実行と依存関係管理 | [Python公式](https://www.python.org/downloads/)と[uv公式手順](https://docs.astral.sh/uv/getting-started/installation/)を参照し、`python --version`と`uv --version`で確認する。Pythonの版はサービスの`pyproject.toml`に合わせる。 |
| AWS CLI | AWSの設定・認証と操作 | AWS操作を行う場合、[AWS公式手順](https://docs.aws.amazon.com/cli/latest/userguide/getting-started-install.html)で導入し、`aws --version`で確認する。 |
| Docker | Lambdaのコンテナイメージのビルド | コンテナ形式を採用する場合、[Docker Desktop公式手順](https://docs.docker.com/desktop/setup/install/windows-install/)で導入し、起動後に`docker version`で確認する。 |

pnpmはnpmから導入できる。プロジェクトが指定する版を確認し、次の`<pnpmのバージョン>`を置き換えて実行する。

```powershell
npm install -g pnpm@<pnpmのバージョン>
pnpm --version
```

AWS CDKとPlaywrightは各プロジェクトの`package.json`で管理する。依存関係の導入後にローカルのコマンドを使い、グローバル版のインストールを前提にしない。
AWSに接続する場合は担当者が定めた認証手順を使い、認証情報をリポジトリに保存しない。

## 2. 画面の依存関係をインストールする

`nuxt/package.json`と`nuxt/pnpm-lock.yaml`があること、および指定されたpnpmのバージョンを確認する。
リポジトリのルートから次を実行する。

```powershell
Push-Location nuxt
pnpm install --frozen-lockfile
Pop-Location
```

エラーなく完了することを確認する。型チェック用スクリプトが`package.json`に定義されている場合は、`nuxt/`で`pnpm typecheck`を実行し、エラーがないことを確認する。

環境設定の見本`nuxt/public/config.example.json`がある場合は、`nuxt/public/config.json`を作成し、担当者から確認した公開可能な値を設定する。

```powershell
Copy-Item nuxt/public/config.example.json nuxt/public/config.json
```

既存の`config.json`は内容を確認せずに上書きしない。パスワードや秘密鍵をこのファイルに記載せず、Gitにコミットしない。設定方針は[フロントエンド実装方針](../../nuxt/docs/20_rules/フロントエンド実装方針.md)を参照する。

## 3. E2Eテストの依存関係とブラウザーをインストールする

`e2e/package.json`、`e2e/package-lock.json`にPlaywrightの依存関係が定義されていることを確認する。
リポジトリのルートから次を実行する。

```powershell
Push-Location e2e
npm ci
npx playwright install chromium
Pop-Location
```

エラーなく完了することを確認する。Playwrightの設定とテストが用意されている場合は、`e2e/`で`npx playwright test --list`を実行し、テストの一覧を確認する。
FirefoxやWebKitも対象にする場合は、プロジェクトのテスト方針に従って追加する。

## 4. 担当するサービスを準備する

Pythonサービスでは、`backend/<サービス名>/`の`pyproject.toml`と`uv.lock`を確認し、サービスのインストール手順に従う。
CDKやAPIテストにNode.jsを使うサービスでは、同じ場所の`package.json`とロックファイルも確認する。
サービスごとの手順と接続先、必要な権限は、対象サービスの`docs/10_installation/`に記載する。

## 5. 準備結果を確認する

ツールのバージョンが表示され、対象の依存関係の導入と、用意されている型チェック・テスト一覧の確認が成功したことを確かめる。
画面やサービスの起動、接続先と停止方法は、実際の構成に基づくローカル動作確認手順に従う。

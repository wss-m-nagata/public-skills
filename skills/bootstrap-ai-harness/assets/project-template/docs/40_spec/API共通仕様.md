# API共通仕様

webappの画面から呼び出すAPIに共通する入出力を定める。  
APIごとのパス、項目、条件とエラーは、各サービスのAPI仕様に従う。

## 要求

- 画面は同じドメインの`/<サービス名>/`配下を呼び出す。
- 認証・認可は[アーキテクチャ.md](../20_rules/アーキテクチャ.md)に従う。
- 日付の形式をAPIで指定する場合は、APIごとの仕様に記載する。

## 応答

- JSONを返すAPIの文字コードはUTF-8とする。
- 正常時の本文は、APIごとの仕様に定めたオブジェクト、配列または値とする。
- APIが返すエラー時の本文は、次の3項目を持つJSONとする。
- 想定外のエラーには利用者向けの一般的な文言を返し、内部のエラー詳細や接続情報を含めない。

| 項目 | 型 | 内容 |
| --- | --- | --- |
| `error_code` | 文字列 | エラーを識別するメッセージID |
| `message` | 文字列 | 利用者向けの日本語の文言。メッセージIDは含めない |
| `detail` | 文字列または`null` | エラーの補足情報。内部のエラー詳細や接続情報は含めず、5xxでは`null`とする |

```json
{
  "error_code": "E001",
  "message": "入力内容を確認してください。",
  "detail": null
}
```

API Gatewayなど、Lambdaに到達する前のエラーは、APIの本文と異なる場合がある。  
画面は応答本文を読めない場合も扱えるようにする。

## ステータス

| ステータス | 意味 |
| --- | --- |
| 400 | 入力の形式や内容が正しくない |
| 401 | 認証情報がない、または有効でない |
| 403 | 実行する権限がない |
| 404 | 対象のAPIまたは指定されたデータがない |
| 405 | 対応していないHTTPメソッドである |
| 409 | 更新対象の状態が競合している |
| 500 | サーバー内部でエラーが発生した |

各APIで返すステータスと条件は、APIごとの仕様に記載する。

## 基本

- CSSファイルはUTF-8、BOMなし、改行はLFで保存する。HTMLまたはCSSの配信時にUTF-8として解釈されるようにする。
- 外部CSSで文字コード宣言が必要な場合は、`@charset "UTF-8";`をファイルの先頭に置く。コメントや空白を宣言より前に置かない。
- CSSファイルの冒頭にCSSの名前を見出しとして書き、対象と役割を1行で説明するコメントを置く。修正履歴が必要な場合は、説明に続けて同じ冒頭に書く。
- Vueの`<style scoped>`の冒頭にも、対象の画面・部品と役割を短いコメントで示す。
- 色の値はVuetifyのテーマに定義し、CSSではテーマの名前を参照する。
- 新しい色は既存の色で表せるか確認し、用途と値を画面設計規約に定める。
- `!important`は原則使用しない。設定やセレクターなどで実現できない場合の最終手段とし、使用箇所に理由を書く。
- セレクターの適用範囲は必要な範囲に限定する。

**理由**: 色を一元管理すると、変更時に個別の画面を修正する必要がなくなる。  
`!important`は後からの上書きを難しくし、スタイルの優先順位を把握しにくくする。

## セレクターとコメント

- 関連するスタイルをまとめると読みやすくなる場合は、CSSのネストを使ってよい。不要な親子関係や深いネストは避け、適用範囲と優先順位を分かりやすくする。
- ネストの最上位のルールの前には、対象となる画面・部品や領域と、スタイルの目的が分かるコメントを書く。
- ネスト内では、対象の状態や画面幅など、ひとまとまりのスタイルが適用される場合と意図を、必要な単位でコメントする。各プロパティにコメントを付ける必要はない。
- ネストしないルールも、対象や意図が名前と値から分かりにくい場合はコメントを付ける。値の繰り返しではなく、何を実現するか、必要に応じて理由を書く。

**理由**: 対象と意図をスタイルの近くに書くと、画面の変更時に影響する範囲と必要な設定を判断しやすい。<br/>
不要なネストやコメントを増やさないことで、構造と重要な説明を追いやすくする。

## CSSの名前

- 自分で定義するクラス名とCSSカスタムプロパティ名は、用途が分かる英小文字のケバブケースを基本とする。例: `.side-panel`、`--header-height`。
- 部品内の要素や状態を区別する場合は、部品名と役割・状態を組み合わせる。例: `.side-panel__label`。
- Vuetifyなど外部ライブラリのクラス名と、既存の共通クラス名は、その定義に従う。

**理由**: 名前から対象や用途を見分けやすくし、画面や部品をまたいで読み方をそろえる。

## 領域の配置と残りの高さ

画面内の領域を配置し、残りの高さを割り当てる場合は、次の基準で方法を選ぶ。

| 方法 | 判断基準 |
|---|---|
| Flexbox | 領域を縦または横の一方向に並べ、残りの空間を配分する場合に検討する。例として、ヘッダー、本文、フッターを縦に並べ、本文に残りの高さを割り当てる。 |
| Grid | 行と列の区切りに合わせて複数の領域を配置する場合に検討する。例として、ヘッダー、サイドメニュー、本文、右側パネル、フッターを行と列に配置する。 |
| `calc(100vh - ...)` | 画面の高さを基準に、周囲の領域の定まった高さを引いて対象の高さを指定する場合に検討する。差し引く値と実際の高さを一致させ、複数の箇所で使う値は共通化する。 |

配置にはまずFlexboxまたはGridを検討し、画面枠の構造や指定する領域を踏まえ、`calc()`で高さを直接表すほうが分かりやすい場合はその方法を使う。<br/>
FlexboxまたはGridと`calc()`は組み合わせてもよい。

スクロール領域は利用可能な高さに収め、内容の末尾と操作を表示できるようにする。<br/>
FlexboxやGridの子要素が内容に引っ張られて縮まない場合は、必要に応じて`min-height: 0`を指定する。<br/>
ビューポートの高さを使う場合は、対象ブラウザーの表示領域に応じて`vh`、`dvh`などを選び、画面の高さを変えた場合にも確認する。

**理由**: 配置方法を領域の構成に合わせて選ぶと、画面の位置関係と高さの決まり方が読み取りやすくなる。<br/>
`calc()`で差し引く値が実際の高さとずれると、内容や操作が隠れたり、不要な余白が生じたりする。<br/>
スクロール領域が縮まらない場合や、ビューポートの高さが実際に見える範囲と異なる場合も、内容や操作が画面外に隠れるため、対象環境で確認する。

配置は[フロントエンド実装方針](./フロントエンド実装方針.md)を参照する。

## 余白の指定

- 余白の値は[画面設計規約の余白](./screen-design-rules/foundations.md#1-余白)に従う。
- 領域の外周の余白は、親要素の`padding`で指定する。
- 要素間の間隔が等しい場合は、FlexboxやGridの親要素の`gap`を基本とする。先頭と末尾の外周に要素間の余白を付けないため。
- 要素ごとに異なる間隔が必要な場合など、`gap`が適さない場合は、後に並ぶ要素の手前側に`margin`を指定する。縦方向は上側、横方向は開始側とし、先頭の表示要素には要素間の余白を付けない。
- 条件付き表示や折り返しを含む場合は、実際に表示される要素の間隔と外周を確認する。`margin`を使う場合は、上下のマージンの相殺にも注意する。

**理由**: 外周と要素間の余白の責任を分けると、要素の追加や削除時に不要な外周の余白が生じにくい。<br/>
後の要素の手前に間隔を指定すると、前の要素が後続の要素の種類や有無を考慮する必要がない。
